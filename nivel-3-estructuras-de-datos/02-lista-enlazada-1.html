Lista enlazada I

Cajas unidas por flechas: crear, recorrer y liberar. ~35 minutos.

Al terminar podrás: escribir una clase ListaEnlazada que mete datos al inicio, los imprime, los cuenta y, al destruirse, libera todos sus nodos sin dejar fugas de memoria.

Por qué esta lección es el centro del curso. La lista enlazada junta todo lo anterior: apuntadores (lección 2.2), new/delete (lección 2.3) y clases (lección 2.4). Y la pila y la cola de las lecciones 3.6 y 7 son esta misma lista con reglas sobre por dónde entrar y salir. Lo que aprendas aquí lo vas a reusar tal cual.

1. El problema del arreglo

Un arreglo es una fila de casillas pegadas en memoria. Si se llena, hay que pedir uno más grande y copiarlo todo (lo hiciste en la lección 2.3). Y meter algo al principio obliga a correr todos los demás un puesto.

La lista enlazada cambia la idea: cada dato vive en su propia caja, en cualquier sitio de la memoria, y cada caja guarda la dirección de la siguiente. Para crecer, se pide una caja más con new y se engancha. No se copia nada (Stanford CS106B, Linked Lists).

2. El nodo: un dato y una flecha

Cada caja se llama nodo. Tiene dos partes: el dato y un apuntador siguiente al próximo nodo. («Apuntador» también se dice «puntero»; aquí usamos siempre «apuntador».)

struct Nodo {
    int dato;            // lo que guardamos
    Nodo* siguiente;     // dirección del próximo nodo (o nullptr)

    Nodo(int d) : dato(d), siguiente(nullptr) {}   // nace sin siguiente
};

Usamos struct porque todo es public (lección 2.4): la lista necesita tocar dato y siguiente directamente. Así se dibuja un nodo. A la izquierda el dato, a la derecha la flecha:

Nodo* a = new Nodo(3);   // a apunta a un nodo nuevo: dato 3, siguiente nullptr

3. Encadenar dos nodos a mano

Si el siguiente del primero guarda la dirección del segundo, ya tienes una cadena:

Nodo* a = new Nodo(3);
a->siguiente = new Nodo(7);   // la flecha del 3 apunta al 7

cout << a->dato;               // 3
cout << a->siguiente->dato;    // 7  — sigue la flecha y lee el dato

Lee a->siguiente->dato de izquierda a derecha, siguiendo flechas: «desde a, salta al siguiente, y lee su dato». El último nodo apunta a nullptr: así se sabe que la lista se acabó.

4. La clase ListaEnlazada: solo guarda la cabeza

La lista entera se maneja con un solo apuntador: la cabeza, que apunta al primer nodo. Desde ahí se llega a todos los demás siguiendo flechas.

class ListaEnlazada {
private:
    Nodo* cabeza;      // primer nodo; nullptr si está vacía
public:
    ListaEnlazada() : cabeza(nullptr) {}           // nace vacía
    bool vacia() { return cabeza == nullptr; }

5. insertarAlInicio, paso a paso

Queremos meter un 5 delante de 3 → 7. Son tres líneas, y el orden importa.

void insertarAlInicio(int valor) {
    Nodo* nuevo = new Nodo(valor);   // 1. crear el nodo aparte
    nuevo->siguiente = cabeza;       // 2. que apunte al que hoy es el primero
    cabeza = nuevo;                  // 3. ahora el primero es él
}

Antes. La lista es 3 → 7.

Paso 1: Nodo* nuevo = new Nodo(5); — el nodo existe, pero todavía no está en la lista. (Lo que cambia en cada paso va en color.)

Paso 2: nuevo->siguiente = cabeza; — copia la dirección que tiene cabeza. Ahora hay dos flechas al 3: la de cabeza y la del 5. No se perdió nada.

Paso 3: cabeza = nuevo; — la cabeza pasa al 5. Al 3 se sigue llegando por la flecha del 5.

Después, dibujado en línea recta:

Funciona también con la lista vacía, sin caso especial: si cabeza es nullptr, el paso 2 deja nuevo->siguiente = nullptr, y el nodo nuevo queda como único y último.

Error típico: mover la cabeza primero. Si inviertes los pasos 2 y 3…

cabeza = nuevo;                // ¡la única flecha al 3 se pierde aquí!
nuevo->siguiente = cabeza;     // el 5 se apunta a sí mismo

…en cuanto cabeza deja de apuntar al 3, nadie guarda su dirección. El 3 y el 7 siguen en memoria, pero ya no puedes llegar a ellos ni liberarlos: es una fuga de memoria. Y además el 5 queda apuntando a sí mismo. Regla: primero engancha lo nuevo, después mueve lo viejo.

6. Recorrer la lista

Para visitar todos los nodos se usa un apuntador auxiliar, actual, que empieza en la cabeza y salta de flecha en flecha hasta llegar a nullptr. Este bucle es el patrón más importante de la lección:

void imprimir() {
    Nodo* actual = cabeza;              // empieza en el primero
    while (actual != nullptr) {         // mientras haya nodo
        cout << actual->dato << " -> ";
        actual = actual->siguiente;     // salta al siguiente
    }
    cout << "nullptr\n";
}
// Con la lista 3, 7, 9 muestra:  3 -> 7 -> 9 -> nullptr

Vuelta 1: actual está en el 3, imprime 3 y salta.

Vuelta 2: está en el 7.

Vuelta 3: está en el 9. Al saltar, copia el siguiente del 9…

…que es nullptr. La condición del while falla y el bucle termina.

tamano() es el mismo recorrido, contando en vez de imprimir:

int tamano() {
    int cuenta = 0;
    Nodo* actual = cabeza;
    while (actual != nullptr) {
        cuenta++;
        actual = actual->siguiente;
    }
    return cuenta;
}

Nunca recorras moviendo cabeza. Si escribes cabeza = cabeza->siguiente dentro del bucle, al terminar cabeza vale nullptr: la lista «se vacía» sola y todos los nodos quedan perdidos. Para mirar, usa siempre una copia: Nodo* actual = cabeza;.

7. El destructor: liberar todos los nodos

Cada nodo se creó con new, así que cada uno necesita su delete. El destructor se ejecuta solo cuando la lista se destruye (LearnCpp, Destructors), y es el sitio para recorrerla borrando:

~ListaEnlazada() {
    Nodo* actual = cabeza;
    while (actual != nullptr) {
        Nodo* sig = actual->siguiente;   // 1. guardar el siguiente
        delete actual;                   // 2. ahora sí, borrar
        actual = sig;                    // 3. avanzar con lo guardado
    }
}

Paso 1: antes de borrar, se apunta sig al siguiente.

Pasos 2 y 3: se libera el 3 y actual avanza gracias a sig. Se repite hasta el final.

Error típico: delete actual; y después actual = actual->siguiente;. Esa segunda línea lee un nodo que ya liberaste (apuntador colgante, lección 2.3). A veces «funciona» por suerte y a veces se cae. Por eso existe sig: lo guardas antes de borrar.

8. Truco didáctico: contar los nodos vivos

¿Cómo sabes que tu destructor liberó todo? En los miniproyectos el Nodo trae un contador global: el constructor lo sube y el destructor del nodo lo baja.

int nodosVivos = 0;

struct Nodo {
    int dato;
    Nodo* siguiente;
    Nodo(int d) : dato(d), siguiente(nullptr) { nodosVivos++; }   // nace uno
    ~Nodo() { nodosVivos--; }                                     // muere uno
};

Si al destruir todas las listas nodosVivos no vuelve a 0, algún nodo se quedó sin delete. Es solo para practicar: en un programa de verdad no hace falta.

¿Qué pasa en la memoria?

Tu ListaEnlazada l; declarada en main vive en la memoria automática (la pila de llamadas o stack), dentro del marco de main, y es diminuta: solo guarda cabeza, un apuntador (normalmente 8 bytes; compruébalo con sizeof(l)). Da igual que tenga 3 nodos o un millón. Los nodos viven en el montón (heap): cada new Nodo pide una caja allí, y sus direcciones no tienen por qué ir seguidas. El contador global nodosVivos está en una tercera zona, la memoria estática.

Las direcciones son inventadas. La lista es la dueña de sus nodos. Al terminar main, C++ llama al destructor de l y luego libera el marco; liberar el marco solo devuelve los bytes de cabeza, no toca el montón. Por eso el destructor recorre la cadena haciendo delete: si no, quedan cajas en el montón a las que no llega ninguna flecha (fuga de memoria).
