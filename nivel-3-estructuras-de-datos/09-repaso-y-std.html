Repaso mezclado y las versiones de fábrica

std::stack, std::queue y std::list: lo que ya hiciste a mano, listo para usar. ~35 minutos.

Al terminar podrás: traducir tu Pila, tu Cola y tu ListaEnlazada a las versiones de C++, elegir cuál usar en cada problema, y programar deshacer/rehacer con dos pilas.

Por qué esta lección. En la universidad te piden escribir la lista, la pila y la cola a mano, con nodos y apuntadores. En la vida real casi nadie lo hace: C++ ya trae las tres hechas y probadas. Saber las dos cosas te sirve dos veces: aprobar el examen y entender qué hay dentro de lo que usarás después. Además, esta lección mezcla preguntas de todo el curso, que es justo como llega el examen.

1. Lo que hiciste a mano ya existe en C++

La biblioteca estándar de C++ (lo que viene con #include) trae contenedores ya hechos. Tres de ellos son tus viejos conocidos:

#include <stack>   // std::stack  → tu Pila
#include <queue>   // std::queue  → tu Cola
#include <list>    // std::list   → tu ListaEnlazada

Entre < > va el tipo de dato que guardan: stack<int> es una pila de enteros, stack<string> una pila de textos. No tienes que saber más de eso por ahora: es la forma de decirle «guarda esto».

No hay new, ni delete, ni destructor que escribir. Cada contenedor libera su memoria solo cuando se destruye.

2. std::stack: tu Pila

Mismos nombres que usaste en la lección 3.6, salvo vacia, que en inglés es empty (cppreference, std::stack).

stack<int> s;
s.push(1);
s.push(2);
s.push(3);               // arriba está el 3
cout << s.top();         // 3   — mira el de arriba sin quitarlo
s.pop();                 // quita el 3
cout << s.top();         // 2
cout << s.size();        // 2
cout << s.empty();       // 0   (false: no está vacía)

Dos trampas de std::stack.

1. pop() no devuelve nada (devuelve void). int x = s.pop(); no compila. Primero lees con top(), luego quitas con pop().

2. Tu Pila hacía «nada» con pop en vacía. La de C++ no te protege: top() o pop() con la pila vacía es comportamiento indefinido (el programa puede caerse o seguir con basura). Pregunta siempre empty() antes.

El patrón que vas a escribir mil veces:

if (!s.empty()) {
    int x = s.top();   // 1) leer
    s.pop();           // 2) quitar
}

3. std::queue: tu Cola

Aquí los nombres sí cambian. Encolar es push (entra por el final), desencolar es pop (sale por el frente) y verFrente es front. Además trae back(), que mira el último (cppreference, std::queue).

queue<string> q;
q.push("Ana");           // encolar
q.push("Beto");
q.push("Caro");
cout << q.front();       // Ana   — el primero que llegó
cout << q.back();        // Caro  — el último que llegó
q.pop();                 // desencolar: se va Ana (pop tampoco devuelve nada)
cout << q.front();       // Beto

Lo delicado de tu Cola (que final vuelva a nullptr al sacar el último) ya lo resuelve std::queue por dentro. Pero la regla de la sección anterior sigue igual: front() o pop() con la cola vacía es un error tuyo, no de C++.

4. std::list: tu ListaEnlazada (con doble flecha)

std::list es una lista enlazada doble: cada nodo apunta al siguiente y al anterior. Por eso puede meter y sacar por los dos extremos igual de rápido (cppreference, std::list).

nodo
dato: 5
← anterior · siguiente →
nodo
dato: 8
← anterior · siguiente →
nodo
dato: 2
← anterior · siguiente →
list<int> l;
l.push_back(5);          // insertarAlFinal
l.push_back(8);
l.push_front(2);         // insertarAlInicio  → 2 5 8
l.remove(5);             // eliminar(5)       → 2 8
for (int x : l) {        // imprimir: recorre de la cabeza al final
    cout << x << " ";
}
cout << l.size();        // 2

Tres diferencias con la tuya:

  • remove(v) borra todos los nodos que valen v, no solo el primero.
  • No hay buscar como método. Se usa find de <algorithm>: if (find(l.begin(), l.end(), 8) != l.end()) significa «el 8 está».
  • No hay l[2]. Igual que en tu lista, para llegar al tercero hay que caminar nodo a nodo.

6. ¿Cuándo usar cada una?

Elige por el orden en que salen las cosas:

Si necesitas…UsaEjemplos
sacar primero lo último que entró (LIFO)piladeshacer, paréntesis balanceados, volver atrás en el navegador
atender en orden de llegada (FIFO)colaturnos del banco, cola de impresión, mensajes
meter y sacar en cualquier puntolistaagenda, lista de tareas que se reordena

En la vida real: usa las de C++. Ya están probadas, no tienen fugas de memoria y cualquiera que lea tu código las reconoce.

En el examen: escribe la tuya, salvo que el enunciado diga lo contrario. Lo que evalúan no es la pila: es si sabes manejar new, delete, apuntadores y casos borde (vacía, un elemento, borrar la cabeza, el final de la cola). Con std::stack todo eso queda escondido, y es justo lo que quieren ver. Si dudas, pregúntale al profesor antes del examen si puedes usar la biblioteca estándar.

7. Dos pilas = deshacer y rehacer

Así funciona Ctrl+Z en un editor. Antes de cada cambio, se guarda el texto como estaba en la pila deshacer. Al deshacer, el texto actual pasa a la pila rehacer y se recupera el de arriba de deshacer.

Escribes «hola», luego «mundo», y deshaces una vez:

texto
"hola"
pilaDeshacer
tope → ""
(lo que había antes de «hola»)
pilaRehacer
tope → "hola mundo"
(lo que acabas de deshacer)

Si ahora escribes algo nuevo, «hola mundo» ya no tiene sentido rehacerlo: escribir vacía la pila de rehacer. Es lo que pasa en cualquier editor real. Eso es el miniproyecto.

¿Qué pasa en la memoria?

Con std::stack, std::queue y std::list no cambia dónde están los datos, sino quién los libera. Como tu Pila, un stack<int> s; declarado en una función vive en su marco, en la memoria automática (la pila de llamadas o stack; nada que ver con std::stack), con un tamaño fijo: sizeof(s) no cambia aunque metas un millón de datos. Los datos van al montón (heap). Al morir s, su destructor libera ese montón solo: es la idea RAII, el objeto es dueño de su memoria y la suelta al morir.

std::list es casi tu lista doble: un nodo por dato, con flecha atrás y adelante. std::stack y std::queue usan por dentro, por defecto, un std::deque, que guarda los datos en bloques de varios elementos, no un nodo por dato. Y los tres copian bien: pilaRehacer = pilaDeshacer; haría una copia profunda sin que escribas la regla de tres.

Miniproyecto 3.9 · Deshacer y rehacer

Abre ejercicios/09-deshacer-rehacer.cpp. Trae una clase Editor con un string texto y dos stack<string>: pilaDeshacer y pilaRehacer. Completa tres métodos:

  1. escribir(palabra): guarda el texto actual en pilaDeshacer, añade la palabra (con un espacio delante si el texto no estaba vacío) y vacía pilaRehacer.
  2. deshacer(): si no hay historial, no hace nada. Si lo hay, guarda el texto actual en pilaRehacer y recupera el de arriba de pilaDeshacer.
  3. rehacer(): lo mismo, con las pilas al revés.

Compílalo desde la carpeta ejercicios:

g++ -std=c++17 -Wall 09-deshacer-rehacer.cpp -o prog && ./prog

Al principio verás varias ✗. Terminaste cuando salgan todas en ✓. Unos 15 minutos.

Si te atascas: recuerda el orden de la sección 2: primero top() para leer, luego pop() para quitar. Y la primera línea de deshacer es if (pilaDeshacer.empty()) return;. La solución está en soluciones/09-deshacer-rehacer.cpp, pero ábrela solo después de intentarlo de verdad.
