Cola

Una lista enlazada con un apuntador extra al final. ~35 minutos.

Al terminar podrás: escribir una clase Cola con dos apuntadores (frente y final) y usarla para simular los turnos de un banco.

Por qué. Pila y cola van juntas en todos los temarios, y casi siempre cae la pregunta «¿qué diferencia hay?». La cola es la otra mitad: sirve cuando hay que atender las cosas en el orden en que llegaron. Y tiene un caso delicado que es justo lo que los profesores corrigen: qué pasa cuando sale el último.

1. La idea: la fila del banco

En la fila del banco, el que llega se pone al final. Y la cajera atiende al que está al frente. Nadie se cuela.

Eso es una cola: el primero que entra es el primero que sale. En inglés, FIFO, «first in, first out» (cppreference, std::queue). Es lo contrario de la pila, donde sale el último.

Otro ejemplo: la impresora de la biblioteca. Si mandan a imprimir Ana, luego Beto, luego Carla, salen en ese orden. Los documentos esperan en una cola.

2. Una cola es una lista con un apuntador extra

Con tu ListaEnlazada ya podrías hacer una cola: sacar por la cabeza y meter con insertarAlFinal. Pero insertarAlFinal (lección 3.3) recorre toda la lista para encontrar el último nodo. Con 10 000 clientes en la fila, cada llegada recorrería 10 000 nodos.

La solución: guardar otro apuntador que siempre señala al último. Así se llega al final de un salto, sin recorrer nada.

El Nodo es el mismo de siempre. La clase:

class Cola {
private:
    Nodo* frente;   // el primero de la fila (el que sale)
    Nodo* final;    // el último de la fila (detrás entra el nuevo)
public:
    Cola() : frente(nullptr), final(nullptr) {}   // vacía: los dos a nullptr
    ~Cola();
    void encolar(int valor);
    void desencolar();
    int  verFrente() const;
    bool vacia() const { return frente == nullptr; }
    int  tamano() const;
};

Fíjate en la regla que la clase debe cumplir siempre: frente y final son nullptr a la vez, o ninguno lo es. Si uno vale nullptr y el otro no, la cola está rota. Esta regla es la clave de toda la lección.

3. encolar: entrar por el final

Hay dos casos:

void Cola::encolar(int valor) {
    Nodo* nuevo = new Nodo(valor);
    if (vacia()) {
        frente = nuevo;              // es el único: es el primero...
        final = nuevo;               // ...y también el último
    } else {
        final->siguiente = nuevo;    // 1. el último de antes lo señala
        final = nuevo;               // 2. el nuevo pasa a ser el último
    }
}

El orden de los dos pasos importa. Si primero haces final = nuevo, ya no sabes cuál era el último de antes, y el 7 nunca queda enlazado con el 9.

5. El caso delicado: sale el último

¿Qué pasa si en la cola queda un solo cliente? Entonces frente y final apuntan al mismo nodo:

Al desencolarlo, frente pasa a frente->siguiente, que es nullptr. Bien. Pero final nadie lo toca: sigue apuntando al nodo que acabas de borrar.

Error típico: olvidar poner final = nullptr al desencolar el último.

Así queda (mal):

final queda como apuntador colgante (lección 2.3): señala memoria liberada. La cola parece vacía porque frente es nullptr, pero rompe la regla de la sección 2. Cualquier código que use final —por ejemplo, un encolar que preguntara if (final == nullptr)— escribiría en un nodo borrado. Es el fallo más corregido en los exámenes de colas porque no se ve al probar: casi siempre «funciona» hasta que no.

El arreglo es una línea:

void Cola::desencolar() {
    if (vacia()) return;            // cola vacía: no hace nada
    Nodo* viejo = frente;
    frente = frente->siguiente;
    if (frente == nullptr) {        // ¡acabo de sacar al último!
        final = nullptr;            // ← la línea que se olvida
    }
    delete viejo;
}

Así queda (bien): los dos a nullptr, como una cola recién creada.

6. Lo demás ya lo sabes

  • verFrente() devuelve frente->dato. Igual que top() de la pila: quien la usa comprueba vacia() antes.
  • vacia() pregunta frente == nullptr.
  • tamano() recorre desde frente contando.
  • El destructor recorre desde frente borrando, igual que el de la pila y el de la lista.

7. Para qué sirve: los turnos del banco

En el miniproyecto simulas una caja de banco. Recibes una lista de eventos, uno detrás de otro:

  • un número mayor que 0 es un cliente que llega con ese número de turno → encolar;
  • un 0 es la cajera que llama al siguiente → si hay alguien, se apunta su turno y se desencola; si la fila está vacía, no pasa nada.

Se atienden 5, 8, 3: en el orden en que llegaron. Con una pila se habrían atendido en otro orden, y el primero en llegar habría esperado más que nadie.

¿Qué pasa en la memoria?

El objeto Cola fila; vive en la memoria automática (la pila de llamadas o stack, que no es tu clase Pila) y guarda solo dos apuntadores. Los dos señalan cajas del montón (heap), donde están los nodos (direcciones inventadas):

Un apuntador es solo una variable con una dirección dentro: nadie le avisa cuando esa caja se libera. Con un solo nodo, frente y final guardan la misma dirección. delete viejo libera la caja; frente ya copió el siguiente (nullptr), pero final conserva la dirección vieja: apuntador colgante. final = nullptr no libera nada; solo borra esa dirección para que nadie la use. Regla: al hacer delete, busca todos los apuntadores que guardaban esa dirección.
