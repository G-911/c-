Pila

Una lista enlazada donde solo se toca la cabeza. ~30 minutos.

Al terminar podrás: escribir una clase Pila con nodos (push, pop, top) y usarla para saber si los paréntesis de un texto están bien cerrados.

Por qué. La pila es la estructura que más aparece en los exámenes después de la lista, y ya tienes casi todo hecho: es tu ListaEnlazada con menos métodos, no con más. Además está por todas partes: el botón «deshacer», el botón «atrás» del navegador y la forma en que un programa recuerda a qué función volver.

1. La idea: una pila de platos

Piensa en una pila de platos para fregar. El plato nuevo se pone encima. Y cuando coges uno, coges el de encima. Nunca sacas el de abajo del todo.

Eso es una pila: el último que entra es el primero que sale. En inglés se dice LIFO, «last in, first out» (cppreference, std::stack).

Otro ejemplo: «deshacer» en un editor. Escribes «Hola», luego «, ¿qué», luego « tal?». Al pulsar Ctrl+Z se deshace primero lo último que hiciste (« tal?»). Cada acción se apila; deshacer saca la de arriba.

Solo hay tres operaciones importantes, con nombres en inglés que verás en todos los libros:

2. Una pila es una lista que solo usa la cabeza

En la lección 3.2 hiciste una ListaEnlazada con un apuntador cabeza al primer nodo. Insertar al inicio era rápido: no hacía falta recorrer nada. Borrar la cabeza (lección 3.3) también.

Una pila es exactamente eso, y nada más. Solo cambian los nombres:

En tu listaEn la pila
cabezatope

insertarAlFinal, buscar, borrar en mediono existen: en una pila solo se toca arriba

Así que la clase usa el mismo Nodo de siempre:

struct Nodo {
    int dato;
    Nodo* siguiente;
    Nodo(int d) : dato(d), siguiente(nullptr) {}
};

class Pila {
private:
    Nodo* tope;                  // el de arriba; nullptr si está vacía
public:
    Pila() : tope(nullptr) {}    // empieza vacía
    ~Pila();                     // libera todos los nodos
    void push(int valor);
    void pop();
    int  top() const;
    bool vacia() const { return tope == nullptr; }
    int  tamano() const;
};

Dibujada, el tope es la cabeza de la lista. El que está más a la izquierda es el de arriba de la pila de platos:

3. push: apilar

Los métodos los escribo fuera de la clase con Pila:: delante, para verlos de uno en uno. Dentro de la clase serían iguales, sin el Pila::.

Son los mismos tres pasos que insertarAlInicio:

void Pila::push(int valor) {
    Nodo* nuevo = new Nodo(valor);   // 1. creo el nodo
    nuevo->siguiente = tope;         // 2. el nuevo apunta al que estaba arriba
    tope = nuevo;                    // 3. ahora el de arriba es el nuevo
}

4. pop: desapilar

Quitar el de arriba es borrar la cabeza de la lista. El orden de los pasos importa:

void Pila::pop() {
    if (vacia()) return;        // pila vacía: no hay nada que quitar
    Nodo* viejo = tope;         // 1. guardo el que voy a borrar
    tope = tope->siguiente;     // 2. bajo el tope al siguiente
    delete viejo;               // 3. ahora sí, lo libero
}

Después: el 9 ya no existe y tope apunta al 7.

Error típico: borrar primero y mover después.

delete tope;
tope = tope->siguiente;   // ✗ tope apunta a un nodo que ya no existe

Después del delete, tope es un apuntador colgante (lección 2.3): leer tope->siguiente es leer memoria liberada. A veces «funciona» por suerte y a veces se cae. Por eso se guarda el nodo en viejo, se mueve el tope y se borra al final.

5. ¿Y si la pila está vacía?

Hay que decidir qué hacen pop y top sin nada que quitar o mirar. En esta guía usamos esta regla, que es la más simple:

  • pop() sobre una pila vacía no hace nada. Lo resuelve el if (vacia()) return; de arriba.
  • top() no se llama con la pila vacía. Quien la usa pregunta antes con vacia(). Es lo mismo que hace std::stack::top: llamarlo vacía es comportamiento indefinido.
int Pila::top() const {
    return tope->dato;          // con tope == nullptr esto se cae
}

// Así se usa bien:
if (!p.vacia()) {
    cout << p.top();
}

Es la misma regla de la lección 2.2: pregunta antes de desreferenciar.

6. El destructor y el truco del contador

Cada push hace un new. Si la pila se destruye con nodos dentro, hay que liberarlos o tendrás una fuga de memoria. El destructor recorre igual que el de tu lista:

Pila::~Pila() {
    Nodo* actual = tope;
    while (actual != nullptr) {
        Nodo* sig = actual->siguiente;   // guardo el siguiente ANTES de borrar
        delete actual;
        actual = sig;
    }
}

tamano() también es el de la lista: recorre contando.

Truco didáctico para ver las fugas. En el miniproyecto el Nodo lleva un contador global nodosVivos: el constructor le suma 1 y el destructor le resta 1. Si al final del programa no vale 0, algún nodo se quedó sin delete. En un programa de verdad no se hace así; aquí sirve para que las pruebas te avisen.

int nodosVivos = 0;
struct Nodo {
    int dato;
    Nodo* siguiente;
    Nodo(int d) : dato(d), siguiente(nullptr) { nodosVivos++; }
    ~Nodo() { nodosVivos--; }
};

7. Para qué sirve: paréntesis balanceados

Un texto como f(a[i]) + {x} está balanceado: cada símbolo que abre se cierra con su pareja, y en el orden correcto. En cambio ([)] no: el ] llega cuando el último abierto era (. Esto lo comprueba cualquier compilador, y se hace con una pila:

  1. Recorre el texto carácter a carácter.
  2. Si abre (( [ {): push.
  3. Si cierra () ] }): mira el top. Si la pila está vacía, o el de arriba no es su pareja, no está balanceado. Si es su pareja, pop.
  4. Al terminar, está balanceado solo si la pila quedó vacía.

¿Por qué una pila? Porque el que se cierra primero es siempre el último que se abrió. Último en entrar, primero en salir.

Un detalle: la pila guarda int, y apilas caracteres. No pasa nada: un char cabe en un int (se guarda su código), y p.top() == '(' compara bien.

¿Qué pasa en la memoria?

No confundas las dos pilas. La memoria automática (la pila de llamadas o stack) es una zona que maneja el compilador: ahí cada función que se está ejecutando tiene su marco. Tu clase Pila es otra cosa: una estructura de datos que programas tú. Solo comparten la idea LIFO.

De hecho, tu Pila p; está repartida en dos zonas. El objeto p vive en el marco de la función que lo declara y solo guarda tope. Los platos —los nodos— están en el montón (heap). Así queda tras push(9) (direcciones inventadas):

Cada push hace un new arriba y cada pop un delete arriba: la memoria que ocupa crece y decrece con los elementos, un nodo por dato. En balanceado, p es local: en cualquier return false se llama a su destructor y libera los nodos que quedaban. Sin destructor, cada texto mal cerrado dejaría una fuga.
