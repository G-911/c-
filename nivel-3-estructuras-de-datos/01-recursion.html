Recursión

Una función que se llama a sí misma con un problema más pequeño. ~30 minutos.

Al terminar podrás: escribir una función recursiva con su caso base y su caso recursivo, y seguir a mano cómo se apilan y se resuelven las llamadas.

Antes de empezar: repite sin mirar el quiz de la lección anterior, Lección 2.7 · Sobrecarga de operadores. Recordar lo de hace días es lo que lo fija.

Por qué empezamos el Nivel 3 aquí. Una lista enlazada es un nodo seguido del resto de la lista. Ese «resto» es otra lista, más corta. Pensar así —un problema que contiene una copia más pequeña de sí mismo— se llama recursión. En la universidad aparece en listas, árboles y algoritmos de ordenamiento, y casi siempre cae en el examen.

1. La idea: resuelve un paso y deja el resto a otra llamada

Una función recursiva se llama a sí misma. Cada llamada recibe un problema un poco más pequeño. Ejemplo: contar hacia atrás.

void cuentaAtras(int n) {
    if (n == 0) {                   // CASO BASE: aquí se para
        cout << "¡Ya!\n";
        return;
    }
    cout << n << " ";               // hago mi parte...
    cuentaAtras(n - 1);             // CASO RECURSIVO: ...y el resto, con n más pequeño
}

cuentaAtras(3);   // 3 2 1 ¡Ya!

Toda función recursiva tiene dos partes:

  • Caso base: un problema tan pequeño que se responde sin llamar a nadie.
  • Caso recursivo: hace un poco de trabajo y se llama con un problema más cercano al caso base.

2. Factorial: el ejemplo clásico

5! = 5 · 4 · 3 · 2 · 1. Fíjate: 5! = 5 · 4!. El factorial de 5 contiene el de 4.

long long factorial(int n) {
    if (n <= 1) return 1;            // caso base: 0! = 1! = 1
    return n * factorial(n - 1);     // caso recursivo: n! = n · (n-1)!
}

cout << factorial(5);   // 120

Para escribir una recursión, no intentes seguir todas las llamadas en la cabeza. Haz un acto de fe: supón que factorial(n - 1) ya funciona y pregúntate solo «con eso, ¿cómo saco factorial(n)?».

3. La pila de llamadas

¿Cómo «espera» factorial(3) a que termine factorial(2)? Cada llamada recibe su propio espacio con sus variables (su n). Esos espacios se apilan uno encima de otro: es la pila de llamadas. La de arriba es la que se está ejecutando. Cuando termina, se quita y la de abajo sigue donde se quedó.

Primero se apila hacia arriba (3, 2, 1). Al llegar al caso base, se desapila hacia abajo, y cada llamada termina su multiplicación con lo que le devolvió la de arriba. Es la misma pila que programarás en la Lección 3.6: la última en entrar es la primera en salir.

El error típico: una recursión que nunca para. Si falta el caso base, o si el caso recursivo no se acerca a él, las llamadas se apilan sin fin. La pila de llamadas es pequeña (unos pocos megabytes), así que se llena y el programa se cae: es un desbordamiento de pila (en inglés, stack overflow).

int mal(int n) {
    if (n == 0) return 1;
    return 2 * mal(n - 2);   // con n = 5: 5, 3, 1, -1, -3... nunca llega a 0
}

Arreglo: el caso base debe atrapar todos los finales posibles (if (n <= 0)), y cada llamada debe acercarse a él.

4. Recursión sobre un arreglo

La suma de un arreglo de n elementos es: el último + la suma de los n - 1 primeros. El caso base es el arreglo vacío, que suma 0.

int sumar(const int arr[], int n) {
    if (n == 0) return 0;                     // arreglo vacío
    return arr[n - 1] + sumar(arr, n - 1);    // el último + el resto
}

int v[] = {4, 1, 7};
cout << sumar(v, 3);   // 12  →  7 + (1 + (4 + 0))

El arreglo no se copia: cada llamada mira el mismo arreglo, pero con un n menor. Achicar el problema es achicar el número.

5. Fibonacci: bonito, pero lento

Cada número de Fibonacci es la suma de los dos anteriores: 0, 1, 1, 2, 3, 5, 8... La versión recursiva copia la definición tal cual:

long long fib(int n) {
    if (n < 2) return n;              // fib(0) = 0, fib(1) = 1
    return fib(n - 1) + fib(n - 2);   // DOS llamadas por cada llamada
}

Funciona, pero cada llamada hace dos, y esas dos hacen cuatro... y muchas repiten el mismo cálculo: fib(5) calcula fib(3) dos veces. fib(40) hace más de 300 millones de llamadas. Un bucle que va guardando los dos últimos valores lo resuelve en 40 pasos. Por qué una es tan lenta y la otra no, lo mides en la Lección 3.8 (complejidad).

6. ¿Recursión o bucle?

Todo lo que hace una recursión lo puede hacer un bucle, y al revés. Regla práctica:

  • Bucle cuando el problema es «repite esto n veces»: es más rápido y no llena la pila.
  • Recursión cuando el problema contiene copias más pequeñas de sí mismo (listas, árboles, dividir a la mitad): el código queda más corto y más claro.

7. Lo que viene: la lista es recursiva

En la próxima lección construyes una lista enlazada: nodos con un dato y un apuntador al siguiente. Mírala con ojos de esta lección: una lista es o vacía (nullptr), o un nodo seguido del resto de la lista.

nodo
dato: 8
siguiente → resto
«el resto»
3 → 5 → nullptr
otra lista, más corta

Así que contar sus nodos tiene la misma forma que sumar:

int contar(Nodo* p) {
    if (p == nullptr) return 0;          // caso base: lista vacía
    return 1 + contar(p->siguiente);     // este nodo + el resto de la lista
}

No hace falta que lo entiendas del todo hoy: el struct Nodo llega en la Lección 3.2. Solo quédate con la forma: caso base = nullptr; caso recursivo = este nodo + el resto.

¿Qué pasa en la memoria?

La pila de llamadas de la sección 3 es una zona real: la memoria automática (la pila de llamadas o stack). Cada llamada ocupa ahí un marco con su propio n y, normalmente, el sitio al que debe volver. factorial(4) llega a tener 4 marcos a la vez, encima del de main; al hacer return, cada marco se libera solo. No es la clase Pila de la lección 3.6: aquella la programas tú y sus nodos viven en el montón (heap); esta la maneja el compilador.

La cuenta que importa: la memoria que gasta una recursión = cuántos marcos hay a la vez (la profundidad), no cuántas llamadas hace en total. fib(40) hace más de 300 millones de llamadas, pero nunca tiene más de unos 40 marcos juntos: se apilan y se desapilan. sumar(v, 3) apila 4 marcos (n = 3, 2, 1, 0), y en cada uno arr es solo una dirección, no una copia del arreglo. Un bucle usa un único marco.

La memoria automática es pequeña (normalmente entre 1 y 8 MB). Una recursión sin caso base, o con millones de niveles, la agota: desbordamiento de pila.

  3. potencia(base, exp): baseexp, con exp >= 0.

g++ -std=c++17 -Wall 01-recursion.cpp -o prog && ./prog
