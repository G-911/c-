Lista enlazada II

Añadir al final, buscar y eliminar sin perder el resto. ~40 minutos.

Al terminar podrás: añadir nodos al final, buscar un valor y eliminar un nodo en cualquier posición —primero, en medio o último— sin perder el resto de la lista ni dejar fugas de memoria.

Por qué. Eliminar un nodo es la pregunta de examen de listas enlazadas: obliga a pensar en flechas, en el orden de las operaciones y en los casos especiales. Y las dos operaciones de hoy son las que usarás en la cola de la lección 3.7: entrar por el final y salir por el principio.

Partimos de la ListaEnlazada de la lección 3.2: un Nodo con dato y siguiente, y la clase con cabeza, insertarAlInicio, imprimir, tamano, vacia y el destructor. Hoy le añadimos tres métodos.

1. insertarAlFinal: llegar al último y engancharse

La clase no sabe dónde está el último nodo: solo tiene cabeza. Así que hay que recorrer hasta encontrarlo. El último es el único cuyo siguiente vale nullptr.

void insertarAlFinal(int valor) {
    Nodo* nuevo = new Nodo(valor);         // nace con siguiente = nullptr
    if (cabeza == nullptr) {               // caso especial: lista vacía
        cabeza = nuevo;
        return;
    }
    Nodo* actual = cabeza;
    while (actual->siguiente != nullptr) { // parar EN el último
        actual = actual->siguiente;
    }
    actual->siguiente = nuevo;             // engancharse detrás
}

Antes de enganchar: actual se detuvo en el 7, porque su siguiente es nullptr. El 9 está creado aparte.

Después de actual->siguiente = nuevo;

Si la lista está vacía no hay «último» al que engancharse: el nodo nuevo pasa directamente a ser la cabeza.

Ojo con la condición del while. En la lección 3.2 el recorrido era while (actual != nullptr), y termina con actual fuera de la lista (en nullptr). Aquí necesitas quedarte sobre el último nodo para tocar su flecha, así que la condición es while (actual->siguiente != nullptr). Con la primera, la línea actual->siguiente = nuevo desreferencia nullptr y el programa se cae.

Fíjate en que insertarAlFinal recorre la lista entera cada vez: con mil nodos, mil saltos. En la cola (lección 3.7) lo arreglaremos guardando un segundo apuntador, final, que siempre apunta al último.

2. buscar: el recorrido con salida temprana

Es el recorrido de siempre, pero en cuanto encuentra el valor sale con return true. Si el bucle termina, es que no estaba.

bool buscar(int valor) {
    Nodo* actual = cabeza;
    while (actual != nullptr) {
        if (actual->dato == valor) return true;   // encontrado: salir ya
        actual = actual->siguiente;
    }
    return false;                                 // recorrí todo y no estaba
}

Con la lista vacía, actual empieza en nullptr, el bucle no se ejecuta y devuelve false. No hace falta caso especial.

3. eliminar: la idea

Para sacar un nodo de la cadena hay que cambiar la flecha que llega a él, para que se lo salte. Esa flecha está en el nodo anterior. Por eso, al recorrer, se llevan dos apuntadores: actual (el que miras) y anterior (el de justo antes).

Hay cinco situaciones. Conviene tenerlas en la cabeza antes de escribir código:

CasoQué hay que hacer
1. Lista vacíanada; devolver false
2. El valor está en la cabezamover cabeza al segundo y liberar el primero
3. Está en medioanterior se salta a actual; liberar actual
4. Es el últimoigual que el 3: anterior pasa a apuntar a nullptr
5. No estáel recorrido llega a nullptr; devolver false

4. Caso: borrar la cabeza

El primer nodo no tiene anterior: la flecha que llega a él no está en ningún nodo, está en cabeza. Así que es la cabeza la que hay que mover.

if (cabeza->dato == valor) {
    Nodo* aBorrar = cabeza;          // 0. recordar cuál borrar
    cabeza = cabeza->siguiente;      // 1. la cabeza pasa al segundo
    delete aBorrar;                  // 2. liberar el antiguo primero
    return true;
}

Antes: queremos borrar el 3.

Paso 1: cabeza = cabeza->siguiente; — la lista ya empieza en el 7. Solo aBorrar recuerda dónde estaba el 3.

Paso 2: delete aBorrar;

La cabeza es un caso especial: trátala aparte, y primero. El código de «borrar en medio» usa anterior->siguiente, pero para el primer nodo no hay anterior: si empiezas con Nodo* anterior = nullptr; y no separas el caso, escribirás nullptr->siguiente y el programa se cae. Y si separas el caso pero haces delete cabeza; antes de moverla, la línea cabeza = cabeza->siguiente lee un nodo ya liberado. Comprueba siempre la cabeza antes del bucle.

5. Caso: borrar en medio

Si la cabeza no era, se recorre con anterior un paso por detrás de actual:

Nodo* anterior = cabeza;
Nodo* actual = cabeza->siguiente;
while (actual != nullptr) {
    if (actual->dato == valor) {
        anterior->siguiente = actual->siguiente;   // 1. reenganchar
        delete actual;                             // 2. ahora sí, liberarlo
        return true;
    }
    anterior = actual;                             // avanzar los dos juntos
    actual = actual->siguiente;
}

Antes: queremos borrar el 7. anterior está en el 3.

Paso 1: anterior->siguiente = actual->siguiente; — la flecha del 3 deja de ir al 7 y va directa al 9. El 7 sigue en memoria y actual todavía lo apunta, pero ya no forma parte de la cadena.

Paso 2: delete actual; — ya nadie lo necesita.

El error clásico: borrar antes de reenganchar. Parece lo mismo cambiar el orden de las dos líneas:

delete actual;                             // ✗ primero borra el 7...
anterior->siguiente = actual->siguiente;   // ✗ ...y luego lee su flecha

Pero la flecha que lleva al 9 estaba dentro del 7. Al liberar el 7 primero, la segunda línea lee memoria liberada (apuntador colgante). Con suerte el programa se cae en el acto; sin suerte sigue funcionando con basura y falla mucho más tarde. Y si la dirección del 9 se pierde, se pierde todo el resto de la lista: fuga de memoria.

Regla: primero reenganchar, después borrar. Antes de cada delete, pregúntate: «¿hay algo dentro de este nodo que todavía necesito?».

6. Caso: borrar el último

No hace falta código nuevo. Si actual es el último, su siguiente es nullptr, y anterior->siguiente = actual->siguiente copia ese nullptr: el penúltimo se convierte en el último.

Antes: queremos borrar el 9.

Después de reenganchar y hacer delete actual:

7. Todo junto: los cinco casos

bool eliminar(int valor) {
    if (cabeza == nullptr) return false;           // caso 1: vacía

    if (cabeza->dato == valor) {                   // caso 2: la cabeza
        Nodo* aBorrar = cabeza;
        cabeza = cabeza->siguiente;
        delete aBorrar;
        return true;
    }

    Nodo* anterior = cabeza;                       // casos 3 y 4
    Nodo* actual = cabeza->siguiente;
    while (actual != nullptr) {
        if (actual->dato == valor) {
            anterior->siguiente = actual->siguiente;
            delete actual;
            return true;
        }
        anterior = actual;
        actual = actual->siguiente;
    }
    return false;                                  // caso 5: no estaba
}

Borra solo la primera aparición del valor y devuelve true o false para que quien llama sepa si encontró algo. Para comprobarlo a mano, prueba los cinco casos en un papel con la lista 3 → 7 → 9: vacía, borrar 3, borrar 7, borrar 9 y borrar 5.

¿Qué pasa en la memoria?

En eliminar, anterior, actual y aBorrar son variables locales: viven en el marco de eliminar, en la memoria automática (la pila de llamadas o stack), y desaparecen solas con el return. Los nodos viven en el montón (heap) y solo se van con delete. Justo después de delete actual; al borrar el 7, queda así (direcciones inventadas):

marco de eliminar
anterior: 0x100
actual: 0x200 (colgante)
memoria automática
nodo 3
siguiente: 0x300
montón · 0x100
(liberado)
aquí estaba el 7
montón · 0x200
nodo 9
siguiente: nullptr
montón · 0x300

delete devuelve la caja al montón pero no cambia la variable actual: sigue guardando 0x200. No pasa nada porque lo siguiente es return true y el marco desaparece. El peligro es leer a través de ella antes: eso es «borrar antes de reenganchar». insertarAlFinal hace lo contrario: la caja de new sobrevive al marco, y su dirección pasa del local nuevo a un nodo de la lista antes de que nuevo muera.
