Sobrecarga de operadores

Que tus clases se sumen, se comparen y se impriman como un int. ~35 minutos.

Al terminar podrás: darle a una clase tuya los operadores ==, !=, + y <<, para escribir a + b y cout << a en vez de sumar(a, b) y a.imprimir().

Antes de empezar: repite sin mirar el quiz de la lección 2.6 · Polimorfismo. Dos minutos. Recordar lo de ayer es lo que hace que no se te olvide.

Por qué. Llevas todo el curso usando operadores sobrecargados sin saberlo: string + string pega textos y cout << imprime de todo. Alguien los escribió para esas clases. Hoy aprendes a hacerlo para las tuyas. Lo necesitas para el Nivel 3: copiar bien una lista enlazada exige escribir operator= (lección 3.5), y poder hacer cout << lista hace mucho más cómodo probarla.

1. Un operador es una función con nombre raro

Para C++, a + b es solo otra forma de escribir una llamada a una función que se llama operator+. Si tu clase tiene esa función, el + funciona con ella.

Usaremos una clase sencilla, un punto en el plano:

class Punto {
private:
    int x, y;
public:
    Punto(int px = 0, int py = 0) : x(px), y(py) {}
    // aquí irán los operadores
};

Sin operadores, Punto(1, 2) == Punto(1, 2) no compila: el compilador no sabe qué significa «igual» para un Punto. Se lo vas a decir tú.

2. operator== y operator!=

Se escriben como métodos. Reciben el otro objeto por const & (lección 2.1: sin copia y sin tocarlo):

bool operator==(const Punto& otro) const {
    return x == otro.x && y == otro.y;
}
bool operator!=(const Punto& otro) const {
    return !(*this == otro);      // reutiliza el ==: «distinto» es «no igual»
}

Cuando escribes a == b, C++ llama a a.operator==(b). El de la izquierda es «yo» (*this); el de la derecha es otro.

El const del final, después de los paréntesis, promete que el método no cambia el objeto. Comparar no debería cambiar nada, así que lo lleva. Así también se puede comparar un const Punto&.

3. operator+: devuelve un objeto nuevo

Cuando haces 3 + 4, ni el 3 ni el 4 cambian: sale un 7 nuevo. Tu + debe portarse igual: construye un Punto nuevo y lo devuelve por valor.

Punto operator+(const Punto& otro) const {
    return Punto(x + otro.x, y + otro.y);   // nuevo; a y b quedan igual
}

Punto a(1, 2), b(10, 20);
Punto c = a + b;     // c vale (11, 22); a sigue (1, 2)

El error típico: que + cambie al de la izquierda.

Punto operator+(const Punto& otro) {
    x = x + otro.x;     // MAL: modifica a *this
    y = y + otro.y;
    return *this;
}

Compila, y c = a + b da bien el resultado. Pero a también cambió, y nadie lo espera. Por eso el + lleva const al final: si lo pones, este error ya no compila.

4. operator<< con friend: imprimir

Aquí hay un problema. En cout << p, el de la izquierda es cout, no tu Punto. Un método de Punto siempre tiene al Punto a la izquierda, así que << no puede ser un método. Tiene que ser una función normal con dos parámetros: el flujo y el punto.

Pero una función normal no puede leer x e y, que son private. La solución es declararla friend dentro de la clase: «esta función no es mía, pero le dejo ver mis privados».

class Punto {
    // ... lo de antes ...
    friend ostream& operator<<(ostream& os, const Punto& p) {
        os << "(" << p.x << ", " << p.y << ")";
        return os;      // ¡imprescindible!
    }
};

Punto a(1, 2);
cout << "a = " << a << "\n";    // a = (1, 2)

Tres detalles, y los tres salen de la lección 2.1:

  • ostream& os: cout no se puede copiar, así que llega por referencia. Escribe en os, no en cout: así también sirve para archivos.
  • const Punto& p: para imprimir solo hace falta leer.
  • return os; devuelve el mismo flujo. Gracias a eso se encadena: cout << a << b es (cout << a) << b, y el paréntesis vale cout otra vez.

Dos fallos clásicos con <<:

1) Escribirlo como método sin friend: ostream& operator<<(ostream& os) dentro de la clase. Entonces el Punto queda a la izquierda y tendrías que escribir p << cout. Con dos parámetros y sin friend no compila: un método solo puede recibir un parámetro aquí.

2) Olvidar return os;. El compilador avisa con -Wall, y si lo ignoras el programa puede caerse al encadenar. Lee los avisos.

5. ¿Cuándo tiene sentido?

Solo cuando el significado sea obvio para cualquiera que lea el código.

BienMal
fraccion1 + fraccion2: sumar es sumarempleado1 + empleado2: ¿qué sería eso?
punto1 == punto2: mismas coordenadaslista + 5 para insertar: usa insertarAlFinal(5)
cout << pila: imprimirla- que en realidad multiplica

Si dudas, usa una función con nombre. Y hay límites que no puedes saltarte (LearnCpp 21.1):

  • No puedes inventar operadores nuevos (no existe **).
  • No puedes cambiar la precedencia: a + b * c sigue haciendo antes el *.
  • Al menos un operando tiene que ser de tu clase: no puedes cambiar int + int.

Más adelante: operator= (asignar) también se sobrecarga. C++ te da uno automático, y con una lista enlazada ese automático la rompe. Lo arreglarás en la lección 3.5.

¿Qué pasa en la memoria?

En Punto c = a + b;, operator+ recibe a b por const & (no se copia) y a a como *this. Dentro, Punto(x + otro.x, y + otro.y) crea un objeto nuevo que sale por valor y se convierte en c; desde C++17 ese return no hace una copia extra. a y b no se tocan.

operator= es otra cosa: no crea nada, copia dentro de un objeto que ya existe. Con un Punto o una Fraccion eso son unos pocos números. Con una lista enlazada, el automático copiaría solo el apuntador cabeza: dos listas dueñas de los mismos nodos (lección 3.5).

Y cout es un único objeto global, en la memoria estática: por eso llega como ostream& os y nunca se copia.

  1. == y != (el segundo, reutilizando el primero).
  2. + y *, que devuelven una Fraccion nueva.
  3. <, para saber cuál es menor.

g++ -std=c++17 -Wall 07-sobrecarga-de-operadores.cpp -o prog && ./prog

Si te atascas: haz las cuentas en papel primero: 1/2 + 1/3 = (1·3 + 1·2) / (2·3) = 5/6. En el código eso es Fraccion(num * otra.den + otra.num * den, den * otra.den). No te preocupes por simplificar: lo hace el constructor.
