Herencia

Escribir lo común una vez y que otras clases lo hereden. ~35 minutos.

Al terminar podrás: crear una clase hija a partir de otra (class Circulo : public Figura), usar protected, llamar al constructor de la base desde la lista de inicialización y saber en qué orden nacen y mueren las dos partes del objeto.

Antes de empezar: repite sin mirar el quiz de la lección 2.4 · Clases. Dos minutos. Recordar lo de ayer es lo que hace que no se te olvide.

Por qué. La herencia es uno de los tres pilares de la POO, y en la universidad es pregunta fija de examen. Además prepara la lección que viene, polimorfismo: guardar círculos y rectángulos en la misma lista y tratarlos igual. Y en el mundo real la verás en todas partes: en los motores de juegos, cada enemigo «es un» personaje.

1. La idea: «es un»

Imagina que haces un programa de dibujo. Un círculo y un rectángulo son distintos, pero los dos tienen cosas en común: un nombre, un color, una posición. Si escribes dos clases separadas, copias ese código dos veces. Y cuando cambie, tendrás que arreglarlo en dos sitios.

La herencia lo resuelve así: escribes lo común una sola vez en una clase base (Figura), y las clases derivadas (Circulo, Rectangulo) lo reciben solas y añaden lo suyo. También se dice clase padre e hija.

La prueba para saber si toca heredar: ¿puedes decir «un Circulo es una Figura»? Sí. Entonces hereda. «Un Motor es un Coche» suena mal: el coche tiene un motor. Eso no es herencia: es un atributo (LearnCpp 24.1).

2. La sintaxis: : public Base

class Figura {                    // la BASE: lo común
public:
    string nombre;
    string getNombre() { return nombre; }
};

class Circulo : public Figura {   // Circulo HEREDA de Figura
public:
    double radio;                 // lo nuevo, solo del círculo
};

Circulo c;
c.nombre = "rueda";      // heredado: no lo escribiste en Circulo
c.radio = 2;             // propio
cout << c.getNombre();   // rueda  (método heredado)

Lee class Circulo : public Figura como «Circulo es una Figura, y además…». La palabra public ahí es la herencia normal: lo público de Figura sigue siendo público en Circulo. En este curso siempre usarás public al heredar.

Por dentro, un objeto Circulo lleva una parte Figura y, pegada, su parte propia:

c · parte Figura
nombre: "rueda"
heredada
c · parte Circulo
radio: 2
propia

Son un solo objeto: las dos cajas van juntas en memoria, una detrás de la otra.

3. protected: privado, pero para la familia

En el ejemplo de arriba nombre era público, y ya sabes que los atributos deben ser private. Pero hay una sorpresa: lo private de la base tampoco lo ve la hija.

class Figura {
private:
    string nombre;
};
class Circulo : public Figura {
public:
    void mostrar() { cout << nombre; }   // ERROR: nombre es private de Figura
};

Para eso existe un tercer nivel, protected: las hijas sí lo ven; desde fuera, nadie (LearnCpp 24.5).

Si el miembro es…¿Lo usa la propia clase?¿Lo usa una hija?¿Lo usa main?
publicsísísí
protectedsísíno
privatesínono

Regla práctica: lo que las hijas necesiten leer, protected; lo demás, private. Una hija también puede usar los métodos públicos de la base, como getNombre(), sin ningún permiso especial.

4. El constructor de la base

Ahora con constructores, como se hace de verdad:

class Figura {
protected:
    string nombre;
public:
    Figura(string n) : nombre(n) {}
    string getNombre() { return nombre; }
};

class Circulo : public Figura {
private:
    double radio;
public:
    Circulo(double r) : Figura("circulo"), radio(r) {}
    //                  ^^^^^^^^^^^^^^^^^ primero: construir la parte Figura
    //                                     ^^^^^^^^ después: lo propio
    double area() { return 3.14159 * radio * radio; }
};

class Rectangulo : public Figura {
private:
    double ancho, alto;
public:
    Rectangulo(double an, double al) : Figura("rectangulo"), ancho(an), alto(al) {}
    double area() { return ancho * alto; }
};

La hija no puede inicializar nombre ella misma: nombre pertenece a la parte Figura, y esa parte la construye el constructor de Figura. Por eso se le llama en la lista de inicialización, escribiendo el nombre de la base como si fuera un atributo (LearnCpp 24.4).

El orden. Al nacer, primero la base y después la hija: no puedes construir el segundo piso sin el primero. Al morir, al revés: primero el destructor de la hija y después el de la base (LearnCpp 24.3).

class Base {
public:
    Base()  { cout << "B+ "; }
    ~Base() { cout << "B- "; }
};
class Hija : public Base {
public:
    Hija()  { cout << "H+ "; }
    ~Hija() { cout << "H- "; }
};

int main() {
    Hija h;
}
// Muestra: B+ H+ H- B-

El error típico: no llamar al constructor de la base.

Circulo(double r) : radio(r) {}   // ¿y la parte Figura?

Si no lo llamas tú, C++ intenta llamar a Figura() sin argumentos. Como Figura solo tiene Figura(string n), no compila, con un mensaje como no matching function for call to 'Figura::Figura()'. Cuando lo veas, ya sabes: falta : Figura(...) al principio de la lista.

5. Añadir y cambiar comportamiento

Una hija puede hacer dos cosas con lo que hereda:

  • Añadir métodos nuevos: Circulo tiene area() y la base no.
  • Redefinir un método de la base: escribir uno con el mismo nombre y los mismos parámetros. Entonces, en un Circulo, gana el del Circulo (LearnCpp 24.7).
class Figura {
    // ... lo de antes ...
    string describir() { return "una figura"; }
};
class Circulo : public Figura {
    // ... lo de antes ...
    string describir() { return "un circulo"; }   // redefine
};

Circulo c(2);
cout << c.describir();   // un circulo

Y aquí viene el adelanto de la próxima lección. Un apuntador a Figura puede apuntar a un Circulo, porque un círculo es una figura:

Figura* p = new Circulo(2);
cout << p->describir();   // una figura   ← ¡la versión de Figura!
delete p;

C++ mira el tipo del apuntador (Figura*), no el objeto de verdad. Eso es justo lo que arregla la palabra virtual en la lección 2.6.

Nota sobre el delete p de arriba: borrar un Circulo a través de un Figura* también necesita virtual (en el destructor). Hoy no lo hagas en tus programas; en la 2.6 verás por qué y cómo.

¿Qué pasa en la memoria?

Un Circulo no es un objeto que «enlaza» con una Figura: la parte Figura va dentro de él, en el mismo bloque, junto a su radio. Por eso un Circulo nunca ocupa menos que una Figura: compáralo con sizeof(Circulo) y sizeof(Figura).

El orden B+ H+ H- B- sale de ahí: la parte de la base se construye primero porque la hija puede necesitarla ya montada, y se destruye la última porque la hija pudo seguir usándola hasta su propio destructor. Ojo: nombre es un string, y sus letras normalmente están en el montón (heap), salvo textos muy cortos; es el destructor de string quien las libera, sin que tú hagas nada.

Con Figura* p = new Circulo(2), el objeto entero vive en el montón y p apunta a su parte Figura. Liberarlo bien a través de ese apuntador es justo lo que arregla la lección 2.6.

Abre ejercicios/05-herencia.cpp. La clase base Empleado ya está hecha: guarda nombre y sueldoBase como protected. Tú completas sus dos hijas:

  1. Gerente: su constructor (pasando los datos a la base) y sueldoTotal() = sueldo base + bono.
  2. Gerente::describir(), que devuelve "Ana (gerente)".
  3. Vendedor: su constructor (las ventas empiezan en 0), registrarVenta(monto) que ignora montos de 0 o negativos, y sueldoTotal() = sueldo base + 10 % de las ventas.

Compílalo desde la carpeta ejercicios:

g++ -std=c++17 -Wall 05-herencia.cpp -o prog && ./prog

Al principio verás casi todo en ✗. Terminaste cuando salga todo en ✓. Unos 20 minutos.

Si te atascas: empieza por los dos constructores; sin ellos fallan casi todas las pruebas. El del gerente queda así: Gerente(string n, double s, double b) : Empleado(n, s), bono(b) {}. El del vendedor es igual, con ventas(0). Y dentro de los métodos de las hijas puedes usar sueldoBase directamente: es protected.
