Clases y objetos

Juntar datos y funciones en una sola pieza que se cuida sola. ~35 minutos.

Al terminar podrás: escribir una clase con atributos private, métodos public, constructor y destructor, y usar un objeto creado con new mediante el operador ->.

Por qué ahora. En la universidad te van a pedir la lista, la pila y la cola como clases. Una ListaEnlazada es un objeto que guarda la cabeza de la cadena de nodos, la protege de que alguien la rompa y, al morir, libera todos sus nodos. Eso son exactamente las tres herramientas de hoy: private, el destructor y el operador ->. Las vas a escribir en todas las lecciones que quedan.

1. Una clase junta datos y funciones

En la lección 2.3 el arreglo dinámico eran tres variables sueltas (el apuntador, el tamaño y la capacidad) y unas funciones que las recibían. Nada impedía que alguien cambiara el tamaño a mano y lo dejara todo incoherente.

Una clase es un tipo nuevo que junta en un solo lugar los atributos (los datos) y los métodos (las funciones que trabajan con esos datos). Un objeto es una variable de ese tipo.

class Contador {
private:
    int valor;                  // atributo: el dato
public:
    Contador() : valor(0) {}    // constructor (sección 3)
    void sumar() { valor++; }   // método: trabaja con SU valor
    int ver() { return valor; } // método que solo consulta
};                              // ¡ojo con este punto y coma!

Contador a;      // a es un objeto de tipo Contador
Contador b;      // b es OTRO objeto, con su propio valor
a.sumar();
a.sumar();
b.sumar();
cout << a.ver() << " " << b.ver();   // 2 1

La clase es el plano; cada objeto es una casa hecha con ese plano. Cada objeto tiene sus propios atributos: sumar en a no toca a b. A los miembros de un objeto normal se llega con el punto: a.sumar().

2. private y public: la encapsulación

Lo que está en public se puede usar desde fuera de la clase. Lo que está en private solo lo pueden tocar los métodos de la propia clase. Desde fuera, ni siquiera compila (LearnCpp, Public and private members):

Contador a;
a.sumar();       // bien: sumar es public
a.valor = -50;   // ERROR de compilación: valor es private

La regla de oro: atributos private, métodos public. A esto se le llama encapsulación. ¿Por qué molestarse? Porque así la clase es la única que puede cambiar sus datos, y puede garantizar que siempre estén bien. Un contador que solo sabe sumar nunca puede valer −50.

Con las listas esto es vital. Una ListaEnlazada guarda un solo apuntador, cabeza, al primer nodo. Todo lo demás se alcanza siguiendo las flechas desde ahí:

lista
cabeza: 0x300 →
nodo
dato: 7
siguiente: 0x340 →
dirección: 0x300
nodo
dato: 4
siguiente: nullptr
dirección: 0x340

Si cabeza fuera pública, bastaría un descuido como lista.cabeza = nullptr; para perder la única flecha que lleva a los nodos. Seguirían ocupando memoria, pero ya nadie podría llegar a ellos para liberarlos: una fuga de memoria. Con cabeza en private, ese error ni compila; solo los métodos de la lista (insertar, eliminar…) la mueven, y los escribes tú con cuidado una sola vez.

Para que desde fuera se pueda leer un dato privado sin poder cambiarlo, se escribe un método que lo devuelve, como ver() arriba. Se suele llamar getAlgo(): «getter».

3. El constructor: nacer bien

El constructor es un método especial que se ejecuta solo, una vez, cuando el objeto nace. Se llama igual que la clase y no devuelve nada (ni siquiera void). Su trabajo: dejar los atributos con valores correctos desde el primer instante.

La forma recomendada es la lista de inicialización: dos puntos después de los paréntesis, y cada atributo con su valor entre paréntesis (LearnCpp, Member initializer lists):

class Punto {
private:
    int x;
    int y;
public:
    Punto(int px, int py) : x(px), y(py) {}   // x empieza en px, y en py
    int getX() { return x; }
};

Punto p(2, 3);        // llama al constructor con 2 y 3
cout << p.getX();     // 2

Así nunca existe un Punto con basura dentro. En la lección 3.2 verás este mismo patrón en el nodo: Nodo(int d) : dato(d), siguiente(nullptr) {}, que garantiza que un nodo recién creado nunca tiene una flecha suelta.

4. El destructor: morir limpio

El destructor es el opuesto: se ejecuta solo, una vez, cuando el objeto muere. Se llama como la clase con una tilde delante (~), no recibe nada y no devuelve nada.

¿Cuándo muere un objeto?

  • Un objeto normal, al llegar a la } del bloque donde se declaró.
  • Un objeto creado con new, cuando haces delete. Ni antes ni después.
class Ruido {
public:
    Ruido()  { cout << "nace ";   }
    ~Ruido() { cout << "muere ";  }
};

int main() {
    {
        Ruido r;           // "nace "
        cout << "usa ";
    }                      // aquí acaba el bloque: "muere "
    cout << "fin";
}
// Muestra: nace usa muere fin

Para qué sirve de verdad: si un objeto pidió memoria con new, su destructor es el lugar donde la devuelve con delete. Quien usa el objeto ya no tiene que acordarse de nada (LearnCpp, Destructors):

class Arreglo {
private:
    int* datos;
public:
    Arreglo(int n) : datos(new int[n]) {}   // pide memoria al nacer
    ~Arreglo() { delete[] datos; }          // la devuelve al morir
};

void f() {
    Arreglo a(1000);
    // ... usarlo ...
}   // a muere aquí, su destructor libera los 1000 int. Cero fugas.

El destructor de tu ListaEnlazada hará lo mismo, pero recorriendo la cadena y borrando nodo por nodo. Sin él, cada lista que muere deja todos sus nodos perdidos en memoria.

Error típico: crear con new y olvidar el delete.

El destructor de un objeto creado con new solo se ejecuta al hacer delete. Si lo olvidas, el objeto nunca muere: ni se libera él ni lo que él tenía reservado. Regla: cada new tiene su delete, y después pones el apuntador en nullptr (lección 2.3).

5. Objetos con new y el operador ->

Un objeto también se puede crear con new. Lo que recibes es un apuntador al objeto, no el objeto:

Punto* p = new Punto(2, 3);   // p guarda la DIRECCIÓN del objeto
p
valor: 0x500 →
dirección: 0x200
objeto Punto
x: 2
y: 3
dirección: 0x500

Para llegar a un miembro hay que desreferenciar primero y luego usar el punto: (*p).getX(). Como esto se escribe muchísimo, C++ tiene un atajo: la flecha -> (LearnCpp, Member selection with pointers).

cout << (*p).getX();   // 2  — forma larga
cout << p->getX();     // 2  — lo mismo, con la flecha
delete p;              // aquí se ejecuta el destructor de Punto
p = nullptr;

La regla para no dudar nunca:

TienesUsasEjemplo
un objetopunto .a.sumar()
un apuntador a objetoflecha ->p->sumar()

En las listas vas a vivir con la flecha: actual->dato, actual->siguiente, cabeza->siguiente->dato… Léela como «del nodo al que apunta actual, su campo dato».

Error típico: *p.getX() sin paréntesis. El punto se aplica antes que el *, así que C++ entiende *(p.getX()) y no compila: p es un apuntador y no tiene punto. Escribe p->getX() y te olvidas del problema. Y si p vale nullptr, p-> es tan grave como *p: el programa se cae.

6. this, en una línea

Dentro de un método, this es un apuntador al objeto que está ejecutando ese método (LearnCpp, The hidden this pointer). Casi nunca hace falta escribirlo. Su uso típico: cuando un parámetro se llama igual que un atributo.

void setX(int x) { this->x = x; }   // this->x es el atributo; x a secas, el parámetro

Fíjate: this es un apuntador, así que va con flecha.

7. struct es casi lo mismo

En C++, struct y class son lo mismo con una sola diferencia: en struct todo es public si no dices nada; en class, todo es private.

struct Nodo {          // todo public: la lista lo manipula directamente
    int dato;
    Nodo* siguiente;
};

La costumbre (y la de este curso): struct para piezas sencillas sin reglas que proteger, como el Nodo; class para lo que tiene que cuidar sus datos, como ListaEnlazada, Pila y Cola. El nodo puede ser público porque solo lo toca la lista, y la lista sí guarda su cabeza en private.

¿Qué pasa en la memoria?

Un objeto en memoria son solo sus atributos, juntos. a y b son dos cajas en el marco de main (memoria automática, la pila de llamadas o stack), cada una con su propio valor. Los métodos sumar() y ver() no se copian en cada objeto: existen una vez, en la zona de código, y this les dice sobre qué objeto trabajar.

El constructor marca cuándo nace el objeto y el destructor cuándo muere: eso es su tiempo de vida. Punto* p = new Punto(2, 3) deja p en la memoria automática y el objeto en el montón (heap) hasta el delete. En Arreglo a(1000) pasa lo contrario: el objeto, pequeño, vive en el marco de f, pero sus 1000 int están en el montón; el destructor es su dueño y los libera al morir a. Y cuentasVivas, al ser global, vive en la memoria estática: dura todo el programa.

Miniproyecto 2.4 · CuentaBancaria

Abre ejercicios/04-clases.cpp. Tiene la clase CuentaBancaria a medio hacer y unas pruebas que se corrigen solas. El saldo es private: la única forma de cambiarlo es con los métodos que tú escribes, y por eso nunca podrá quedar negativo.

  1. El constructor, con lista de inicialización: el saldo empieza en el valor que recibe y los movimientos en 0.
  2. El destructor: resta 1 al contador cuentasVivas.
  3. depositar(cantidad): suma y cuenta un movimiento; ignora cantidades de 0 o menos.
  4. retirar(cantidad): resta solo si alcanza y devuelve true; si no alcanza, no toca nada y devuelve false.
  5. getSaldo() y getMovimientos(): devuelven los atributos.

Fíjate en que las pruebas crean la cuenta con new y la usan con ->, como harás con los nodos.

El truco del contador. cuentasVivas es una variable global: el constructor le suma 1 y el destructor le resta 1. Si al final del programa no vale 0, alguna cuenta nunca se destruyó. En las lecciones 3.2 a 7 usaremos el mismo truco con los nodos para pillar fugas de memoria sin herramientas especiales.

g++ -std=c++17 -Wall 04-clases.cpp -o prog && ./prog

Si te atascas: dentro de un método, los atributos se usan por su nombre, sin punto ni flecha: saldo += cantidad;. En retirar, comprueba primero el caso malo y sal con return false;; lo que queda debajo ya es el caso bueno.
