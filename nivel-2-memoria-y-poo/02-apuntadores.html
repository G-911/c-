Apuntadores

Una variable que guarda la dirección de otra. ~30 minutos.

Al terminar podrás: escribir una función que cambia variables de quien la llama, usando & y *.

Por qué importa. Una lista, una pila y una cola son lo mismo por dentro: cajas (nodos) unidas por apuntadores. Cada nodo guarda un dato y la dirección del siguiente. Si dominas esta lección, las tres estructuras salen casi solas.

1. Toda variable vive en una dirección

La memoria es una fila enorme de casillas numeradas. Cuando escribes int x = 5;, el programa reserva una casilla, le pone el nombre x y guarda un 5. El número de la casilla es su dirección.

El operador & delante de una variable te da su dirección:

int x = 5;
cout << x  << "\n";   // 5               (el valor)
cout << &x << "\n";   // 0x7ffd5e8c       (la dirección; cambia en cada ejecución)

2. Un apuntador guarda una dirección

Un apuntador es una variable cuyo valor es una dirección. Se declara con * después del tipo:

int x = 5;
int* p = &x;   // p guarda la dirección de x.  "p apunta a x"
x
valor: 5
dirección: 0x100
p
valor: 0x100 → x
dirección: 0x200

p también es una variable con su propia casilla. Lo que tiene dentro no es un 5: es dónde está el 5.

3. * para llegar al valor

Delante de un apuntador ya creado, * significa «ve a esa dirección». Se llama desreferenciar. Puedes leer y también escribir:

int x = 5;
int* p = &x;
cout << *p;    // 5   — lee lo que hay donde apunta p
*p = 9;        // escribe 9 donde apunta p... es decir, en x
cout << x;     // 9

El * tiene dos trabajos y confunde a todos al principio:

En una declaración (int* p) dice «p es un apuntador». En una expresión (*p = 9) dice «ve al valor apuntado».

4. nullptr: apuntar a nada

Un apuntador que todavía no apunta a nada válido se inicializa con nullptr. Desreferenciarlo es un error grave: el programa suele caerse (LearnCpp, Null pointers).

int* p = nullptr;
if (p != nullptr) {     // pregunta SIEMPRE antes de usar *p
    cout << *p;
}

Esto lo vas a usar todo el tiempo: el último nodo de una lista apunta a nullptr, y así sabes que se acabó.

5. Para qué sirve: funciones que cambian tus variables

En C++ una función recibe una copia de lo que le pasas. Si cambia la copia, tu variable no se entera:

void doblar(int n) { n = n * 2; }   // dobla la COPIA

int a = 4;
doblar(a);
cout << a;   // 4  — no cambió

Si le pasas la dirección, la función puede ir hasta tu variable y cambiarla:

void doblar(int* n) { *n = *n * 2; }   // va hasta la variable original

int a = 4;
doblar(&a);    // le paso la dirección de a
cout << a;     // 8

Esta es la idea que vas a practicar en el miniproyecto.

¿Qué pasa en la memoria?

En el dibujo de arriba, x y p son dos cajas en el marco de main, su espacio en la memoria automática (la pila de llamadas o stack). Las direcciones 0x100 y 0x200 son inventadas y cortas; las de verdad cambian en cada ejecución. p ocupa sizeof(p) bytes, normalmente 8 en un equipo de 64 bits, apunte a lo que apunte.

En doblar(&a), el marco de doblar recibe una copia de la dirección; la copia lleva a la misma caja a. Nadie libera x ni a a mano: mueren solas al terminar su función. Apuntar a algo no te hace su dueño (quien debe liberarlo). Y si la caja muere mientras el apuntador sigue guardando su dirección, queda un apuntador colgante.

Un apuntador también puede guardar la dirección de una caja del montón (heap), que no muere sola: eso es la lección 2.3.

Miniproyecto 2.2 · intercambiar y minMax

Abre ejercicios/02-apuntadores.cpp. Tiene dos funciones vacías y unas pruebas que se corrigen solas.

  1. intercambiar(int* a, int* b): intercambia los valores de las dos variables.
  2. minMax(int arr[], int n, int* menor, int* mayor): deja el menor y el mayor del arreglo en dos variables de quien llama. Es una función que «devuelve» dos resultados.

Compílalo desde la carpeta ejercicios:

g++ -std=c++17 -Wall 02-apuntadores.cpp -o prog && ./prog

Al principio verás varias ✗. Terminaste cuando salgan todas en ✓. Unos 15 minutos.

Si te atascas: dibuja las cajas en un papel, como en el diagrama de arriba. Casi todos los errores con apuntadores se ven en cuanto dibujas a dónde apunta cada flecha.
