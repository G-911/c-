Funciones

Dale nombre a un trozo de código y reúsalo. ~35 minutos.

Al terminar podrás: escribir funciones con parámetros y return, declararlas con un prototipo, y usar sobrecarga y parámetros por defecto.

Calentamiento (2 minutos): antes de empezar, repite sin mirar el quiz de la lección 1.5 · Bucles. Luego, si te sobra un minuto, el de la 1.4.

Por qué importa. Una clase (Nivel 2) es, en el fondo, datos más funciones que trabajan con ellos. push, pop, insertarAlFinal: todo son funciones. Y en el examen te pedirán «escribe una función que…». Esta es la pieza con la que se construye todo lo demás.

1. Una función es una receta con nombre

Ya conoces una: main. Una función tiene cuatro partes:

int cuadrado(int x) {    // tipo que devuelve · nombre · (parámetros)
    return x * x;        // cuerpo: return entrega el resultado
}

int main() {
    int r = cuadrado(4); // la LLAMADA: x vale 4 dentro; r recibe 16
    cout << cuadrado(r); // 256 — el resultado se usa como cualquier valor
}

Al llamar, el programa salta a la función, la ejecuta y, al llegar a return, vuelve al punto de la llamada con el valor. return termina la función en ese momento: lo que haya debajo no se ejecuta.

2. Parámetros: los datos de entrada

Puede tener varios, separados por comas, cada uno con su tipo. Los valores que pasas al llamar se llaman argumentos y se asignan en orden:

double precioFinal(double precio, int cantidad) {
    return precio * cantidad;
}

precioFinal(2.5, 4);     // precio = 2.5, cantidad = 4 → 10

3. void: funciones que no devuelven nada

Si la función solo hace algo (imprimir, por ejemplo), su tipo es void. No lleva return con valor (puede llevar return; a secas para salir antes).

void linea(int largo) {
    for (int i = 0; i < largo; i++) cout << "-";
    cout << "\n";
}

linea(10);   // ----------

4. Prototipos: avisar antes de usar

El compilador lee de arriba abajo. Si main llama a una función que está escrita más abajo, protesta: «no la conozco». Solución: un prototipo arriba, que es la primera línea de la función con ;:

int cuadrado(int x);          // prototipo: "existe, ya te la daré"

int main() {
    cout << cuadrado(5);      // ahora sí compila
}

int cuadrado(int x) {         // la definición puede ir al final
    return x * x;
}

En el Nivel 4 verás que los prototipos son justo lo que va en los archivos .h.

5. Variables locales: cada función tiene su caja

Una variable creada dentro de una función (y sus parámetros) solo existe ahí dentro. Nace al entrar y desaparece al salir. Otra función no la ve, aunque se llame igual. Eso es el ámbito (en inglés, scope).

int contar() {
    int total = 0;     // se crea de nuevo en CADA llamada
    total++;
    return total;      // siempre devuelve 1
}

6. Se pasa una copia

El parámetro es una copia del argumento. Si la función cambia la copia, la variable de quien llama no se entera:

void sumarUno(int n) { n++; }   // cambia la COPIA

int a = 5;
sumarUno(a);
cout << a;                      // 5 — no cambió

Por eso las funciones de este nivel devuelven el resultado con return. Cómo cambiar la variable original se ve en la lección 2.1 · Referencias.

a (en main)
valor: 5
no la toca nadie
n (en sumarUno)
valor: 5 → 6
copia; desaparece al salir

7. Sobrecarga: mismo nombre, distintos parámetros

Puedes tener varias funciones con el mismo nombre si sus parámetros son distintos (en cantidad o en tipo). El compilador elige la que encaja con la llamada:

int maximo(int a, int b)        { return (a > b) ? a : b; }
int maximo(int a, int b, int c) { return maximo(maximo(a, b), c); }

maximo(3, 8);       // usa la de 2 → 8
maximo(4, 9, 7);    // usa la de 3 → 9

Solo cambiar el tipo de retorno no basta: tienen que cambiar los parámetros.

8. Parámetros por defecto

Un parámetro puede traer un valor por si no lo pasan. Van siempre al final de la lista:

void saludar(string nombre, string saludo = "Hola") {
    cout << saludo << ", " << nombre << "\n";
}

saludar("Ana");             // Hola, Ana
saludar("Ana", "Buenas");   // Buenas, Ana

Si hay prototipo, el valor por defecto se escribe en el prototipo y no se repite en la definición (repetirlo es un error de compilación).

Errores típicos con funciones:

1. Olvidar el return en una función que no es void, o dejar un camino sin él (un if que devuelve y un else que no). Compila con un aviso y devuelve basura. Lee los avisos de -Wall: «control reaches end of non-void function» es exactamente esto.

2. Esperar que la función cambie tu variable sin devolver nada: recibe una copia (punto 6).

3. Llamar a una función escrita más abajo sin prototipo: «was not declared in this scope».

¿Qué pasa en la memoria?

Cada llamada a una función reserva un marco nuevo encima del de quien llama, en la memoria automática (la pila de llamadas o stack; nada que ver con la clase Pila del Nivel 3). En ese marco van sus parámetros, que son copias, y sus variables locales. Al hacer return, el valor sale y el marco se libera entero.

marco de sumarUno
n: 5 → 6
arriba; se libera al terminar
marco de main
a: 5
abajo; espera a que vuelva la llamada

Por eso contar() siempre devuelve 1: su total vive en un marco que se crea en cada llamada y desaparece al salir. Y por eso una variable local no sobrevive a su función. La memoria automática tiene un tamaño limitado: una función que se llama a sí misma sin parar apila marcos hasta desbordarla (lo verás en la lección 3.1, recursión).
