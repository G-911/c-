Variables y tipos

Cajas con nombre, y por qué importa qué cabe en cada una. ~30 minutos.

Calentamiento (3 minutos). Antes de empezar, repite sin mirar el quiz de la lección 1.1. Recordar lo de ayer es lo que lo fija. Si fallas alguna, relee solo esa parte.

Al terminar podrás: elegir el tipo correcto para cada dato (int, double, char, bool, string), inicializarlo con {}, protegerlo con const y reconocer un desbordamiento.

Por qué importa. Una lista enlazada es una cadena de nodos, y cada nodo guarda un dato de algún tipo. Más adelante un apuntador será también una variable, solo que de un tipo especial. Si tienes claro qué es una variable y qué cabe en ella, esas lecciones se entienden mucho mejor.

1. Una variable es una caja con nombre y tipo

Una variable es un trozo de memoria con un nombre. El tipo dice qué cabe dentro y cuánto espacio ocupa.

int edad{20};          // caja "edad", tipo int, guarda 20
double precio{9.99};   // caja "precio", tipo double, guarda 9.99
edad
int · 20
normalmente 4 bytes
precio
double · 9.99
normalmente 8 bytes

El tipo no se cambia nunca: edad será int toda su vida. El valor sí se puede cambiar con =:

edad = 21;             // ahora la caja guarda 21; el 20 se perdió

Para enteros muy grandes existe long long (hasta unos 9 trillones). El decimal se escribe con punto, no con coma: 15.5. Para string hace falta #include <string>.

Con cout un bool se muestra como 1 (true) o 0 (false).

3. Inicializar: siempre, y mejor con {}

Inicializar es darle valor a la caja en el momento de crearla. Hay varias formas:

int a{5};      // con llaves: la forma recomendada
int b = 5;     // con = : también vale, la verás mucho
int c;         // SIN valor: contiene basura (lo que hubiera en esa memoria)

Las llaves tienen una ventaja: no te dejan perder datos sin avisar. Meter un decimal en un int cortaría la parte decimal; con llaves, el compilador lo impide:

int n = 3.7;   // compila y guarda 3 (el .7 se pierde en silencio)
int m{3.7};    // error: narrowing conversion ... from 'double' to 'int'

Narrowing significa «estrechamiento»: meter algo en una caja donde no cabe entero.

Error típico 1: usar una variable sin inicializar.

int total;
total = total + 10;   // ¿basura + 10? El resultado es impredecible

Puede dar 10 en tu computadora y 32777 en la del profesor. Inicializa siempre: int total{0};

4. const: valores que no deben cambiar

const double PI{3.14159};
const int NOTA_MINIMA{10};
PI = 3;        // error: assignment of read-only variable 'PI'

Una constante se fija al crearla y ya no cambia. Si por despiste intentas cambiarla, el compilador te para. Por costumbre se escriben en MAYÚSCULAS. Úsalas para cualquier número «mágico» que tenga significado: es más legible NOTA_MINIMA que un 10 suelto.

5. auto: que el compilador deduzca el tipo

auto x{5};       // int, porque 5 es entero
auto y{2.5};     // double, porque 2.5 tiene decimales
auto z{'k'};     // char

auto no es un tipo nuevo: el compilador mira el valor inicial y pone el tipo por ti. Por eso auto necesita valor inicial. Será muy útil con tipos de nombre larguísimo (lo verás en el nivel 4). Al principio, mejor escribe el tipo: así lo practicas.

6. string básico

string nombre{"Ana"};
string saludo{"Hola, " + nombre + "!"};   // + pega textos: "Hola, Ana!"
cout << saludo << "\n";

Con string, el + concatena (pega uno detrás de otro). Hay muchas más cosas que hacer con textos; las verás en la lección 1.7.

Error típico 2: confundir comillas. 'A' (simples) es un char, un solo carácter. "A" (dobles) es un texto. char letra{"A"}; no compila.

7. Desbordamiento: cuando el número no cabe

Un int tiene un máximo: 2147483647. Si te pasas, el valor no «crece»: se desborda. En un int eso es comportamiento indefinido, y en la práctica suele dar la vuelta al extremo negativo:

int x{2147483647};
x = x + 1;
cout << x;      // -2147483648  ← no es un error de imprenta

El compilador no te avisa: el número se calcula al ejecutar. La solución es elegir un tipo con más espacio:

long long segundos{100};
segundos = segundos * 365 * 24 * 60 * 60;   // 3153600000: en int no cabría

Fíjate en que la cuenta empieza con segundos, que ya es long long. Si la escribes con int y solo al final la guardas en un long long, ya es tarde: el desbordamiento ocurrió a mitad de cuenta. Lo practicarás en el miniproyecto.

¿Qué pasa en la memoria?

Cada variable que declaras dentro de main es una caja en el marco de main, dentro de la memoria automática (la pila de llamadas o stack). La caja mide sizeof(tipo) bytes, y ese tamaño no cambia nunca, igual que el tipo. Las cifras dependen de la computadora; puedes preguntarlas tú mismo:

cout << sizeof(int) << " " << sizeof(double);   // normalmente: 4 8

const no cambia dónde vive la caja: solo prohíbe escribir en ella. La «basura» de int c; es lo que quedó en esos bytes de un uso anterior. Y el desbordamiento es esto: con un int de 4 bytes (lo normal) no cabe nada mayor que 2147483647. La caja no crece para hacerle sitio al +1.
