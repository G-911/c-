Ordenamiento

Cinco formas de ordenar, contando cuánto trabaja cada una. ~40 minutos.

Al terminar podrás: escribir inserción, mergesort y quicksort, decir el coste de cada uno (y el peor caso de quicksort), explicar qué es un ordenamiento estable y elegir entre std::sort y std::stable_sort.

Antes de empezar: repite sin mirar el quiz de la lección 5.4 (montículos y colas de prioridad). Recordar lo de ayer es lo que hace que se quede.

Por qué. En la práctica ordenas con una línea: sort(v.begin(), v.end()) (lección 4.3). Pero los algoritmos de ordenamiento son el tema clásico de los exámenes, y enseñan las dos grandes ideas de la algoritmia: hacer un poco cada vez (los O(n²)) y dividir para vencer (los O(n log n)). Además, la búsqueda binaria de la lección 3.8 solo funciona si antes ordenaste.

1. Cómo vamos a medir: contar comparaciones

Medir el tiempo engaña: cambia con la máquina, con lo que haya abierto, con cada ejecución. Lo que no cambia es cuántas veces compara dos elementos el algoritmo. Eso contaremos.

En todas las trazas usamos el mismo arreglo pequeño:

vector<int> v = {5, 2, 4, 1, 3};

2. Burbuja: los grandes flotan al final

Recorre el vector comparando vecinos; si están al revés, los cambia. Tras cada pasada, el mayor que quedaba ha «flotado» hasta el final, como una burbuja.

void burbuja(vector<int>& v) {
    int n = v.size();
    for (int pasada = 0; pasada < n - 1; pasada++) {
        bool huboCambio = false;
        for (int j = 0; j < n - 1 - pasada; j++) {   // el final ya está listo
            if (v[j] > v[j + 1]) {
                swap(v[j], v[j + 1]);
                huboCambio = true;
            }
        }
        if (!huboCambio) break;                       // nada cambió: ya está ordenado
    }
}

3. Selección: busca el menor y ponlo delante

En cada vuelta busca el menor de la parte sin ordenar y lo intercambia con el primero de esa parte. (Es el que explica LearnCpp 18.1.)

void seleccion(vector<int>& v) {
    int n = v.size();
    for (int i = 0; i < n - 1; i++) {
        int menor = i;
        for (int j = i + 1; j < n; j++)
            if (v[j] < v[menor]) menor = j;
        swap(v[i], v[menor]);                 // un solo intercambio por vuelta
    }
}

4. Inserción: como ordenar cartas en la mano

La parte izquierda ya está ordenada. Toma el siguiente (x), corre a la derecha los mayores que él y déjalo en el hueco.

void insercion(vector<int>& v) {
    for (int i = 1; i < (int)v.size(); i++) {
        int x = v[i];                          // la carta que colocamos
        int j = i - 1;
        while (j >= 0 && v[j] > x) {
            v[j + 1] = v[j];                   // el mayor se corre a la derecha
            j--;
        }
        v[j + 1] = x;                          // x cae en el hueco
    }
}

Total: 9 comparaciones. El peor caso (al revés) es O(n²). Pero si ya está casi ordenado, cada x se para enseguida: con un vector ordenado hace solo n − 1 comparaciones, O(n). Por eso se usa en la práctica para trozos pequeños o casi ordenados.

Error típico: el orden de la condición del while.

while (v[j] > x && j >= 0)   // MAL: con j = -1 lee v[-1] antes de comprobar
while (j >= 0 && v[j] > x)   // BIEN: el && corta si j < 0

Leer v[-1] es comportamiento indefinido: puede «funcionar» en tu prueba y fallar en el examen. El mismo cuidado vale para j < n - 1 - pasada en burbuja: con j < n leerías v[n].

5. Mergesort: partir, ordenar las mitades y mezclar

Idea recursiva (lección 3.1): un vector de 0 o 1 elementos ya está ordenado (caso base). Si no, pártelo en dos mitades, ordena cada una con mergesort y mezcla las dos mitades ordenadas.

Mezclar dos listas ordenadas es fácil: mira el primero de cada una y saca el menor; repite.

void mezclar(vector<int>& v, int ini, int medio, int fin) {   // [ini,medio) y [medio,fin)
    vector<int> temp;                          // memoria EXTRA
    int i = ini, j = medio;
    while (i < medio && j < fin) {
        if (v[j] < v[i]) temp.push_back(v[j++]);   // la derecha solo si es MENOR
        else             temp.push_back(v[i++]);   // empate: gana la izquierda
    }
    while (i < medio) temp.push_back(v[i++]);  // lo que sobre, sin comparar
    while (j < fin)   temp.push_back(v[j++]);
    for (int k = 0; k < (int)temp.size(); k++) v[ini + k] = temp[k];
}

void mergesort(vector<int>& v, int ini, int fin) {
    if (fin - ini <= 1) return;                 // caso base
    int medio = ini + (fin - ini) / 2;
    mergesort(v, ini, medio);
    mergesort(v, medio, fin);
    mezclar(v, ini, medio, fin);
}

6. Quicksort: elegir un pivote y partir

Otra forma de dividir: elige un pivote y particiona: los <= que él a la izquierda, los mayores a la derecha. El pivote queda en su sitio definitivo. Luego ordena cada lado igual. Aquí el pivote es el último (esquema de Lomuto):

int particionar(vector<int>& v, int ini, int fin) {   // fin incluido
    int pivote = v[fin];
    int i = ini;                              // aquí va el siguiente «pequeño»
    for (int j = ini; j < fin; j++) {
        if (v[j] <= pivote) {
            swap(v[i], v[j]);
            i++;
        }
    }
    swap(v[i], v[fin]);                       // el pivote, a su sitio
    return i;
}

void quicksort(vector<int>& v, int ini, int fin) {
    if (ini >= fin) return;
    int p = particionar(v, ini, fin);
    quicksort(v, ini, p - 1);
    quicksort(v, p + 1, fin);
}

El peor caso de quicksort

Si el pivote parte en dos mitades parecidas, son unos log2 n niveles: O(n log n) en promedio. Pero si el pivote es siempre el mayor o el menor, un lado queda vacío y el otro con n − 1: n niveles y O(n²). Con «pivote = último» eso pasa justo con un vector ya ordenado. En el miniproyecto lo vas a medir: 100 elementos ordenados cuestan 4950 comparaciones, las mismas que el peor caso de inserción.

Quicksort no es «siempre O(n log n)». Es O(n log n) en promedio y O(n²) en el peor caso. Las versiones reales eligen mejor el pivote (el del medio, la mediana de tres, uno al azar) y std::sort va más allá: desde C++11 debe hacer O(n log n) comparaciones también en el peor caso, y por eso suele implementarse como introsort, que cambia a heapsort si la recursión se hunde demasiado (cppreference, notas de std::sort).

7. Estabilidad: qué pasa con los empates

Un ordenamiento es estable si los elementos iguales conservan el orden en que venían. Con números sueltos da igual. Importa cuando ordenas registros por un campo:

struct Alumno { string nombre; int nota; };
vector<Alumno> a = {{"Ana", 8}, {"Beto", 6}, {"Caro", 8}, {"Dani", 6}};
// ordenar por nota, de menor a mayor:
// estable:     Beto Dani Ana Caro   (Beto antes que Dani, Ana antes que Caro: como venían)
// no estable:  también podría salir Dani Beto Caro Ana

Por qué la selección no es estable, en un ejemplo de tres: 4a 4b 1. En la primera vuelta el menor es el 1 y se intercambia con 4a, que salta por encima de 4b: queda 1 4b 4a. Los dos 4 cambiaron de orden.

8. En la práctica: std::sort y std::stable_sort

#include <algorithm>

vector<int> v = {3, 1, 2};
sort(v.begin(), v.end());                                  // 1 2 3
sort(v.begin(), v.end(), [](int x, int y) { return x > y; });  // 3 2 1 (al revés)

stable_sort(a.begin(), a.end(),
            [](const Alumno& x, const Alumno& y) { return x.nota < y.nota; });
// Beto Dani Ana Caro: los empates quedan como venían
  • std::sort: O(n log n), no garantiza estabilidad. Tu primera opción.
  • std::stable_sort: garantiza que los iguales conservan su orden (cppreference). O(n log n) si hay memoria extra disponible (suele ser un mergesort). Úsalo cuando ordenas registros y el orden previo importa.
  • La lambda responde «¿x va antes que y?». Debe usar < o >, nunca <=: un elemento no puede ir antes que sí mismo.

¿Qué pasa en la memoria?

Burbuja, selección e inserción ordenan en el sitio: solo usan unas pocas variables (i, j, x) en su marco de la memoria automática (la pila de llamadas o stack), O(1) extra. Mergesort no: cada mezclar crea un vector temp cuyo contenido va al montón (heap) y se libera solo al salir de la función; en total, O(n) extra.

Quicksort tampoco usa vector extra, pero la recursión apila un marco por nivel. En su peor caso son n niveles: con millones de datos ordenados, la pila de llamadas se puede desbordar.
