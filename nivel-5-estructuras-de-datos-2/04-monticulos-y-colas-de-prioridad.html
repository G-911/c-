Montículos y colas de prioridad

Sacar siempre «el más urgente» sin ordenar todo. ~35 minutos.

Al terminar podrás: escribir una clase Monticulo sobre un vector con insertar y extraerMax en O(log n), usar std::priority_queue (de máximos y de mínimos) y explicar cómo ordena el heapsort.

Antes de empezar: repite sin mirar el quiz de la lección 5.3 (árboles balanceados). Recordar lo de ayer es lo que hace que se quede.

Por qué. La Cola de la lección 3.7 atiende por orden de llegada. Pero muchas veces importa la urgencia: la sala de emergencias, las tareas de un sistema operativo, el camino más corto de un mapa (Dijkstra, lección 5.7). Para eso existe la cola de prioridad, y su forma clásica es el montículo. Sale en casi todos los exámenes de estructuras de datos.

1. El problema: siempre el más urgente

Queremos dos operaciones: meter un dato y sacar el mayor. Con lo que ya sabes hay dos formas, y las dos cojean:

Cómo lo guardasMeterSacar el mayor
vector sin ordenarO(1): push_backO(n): hay que buscarlo
vector ordenadoO(n): hay que correr los demásO(1): está al final
montículoO(log n)O(log n)

El montículo no ordena todo: solo garantiza que el mayor está arriba. Ese «orden a medias» es más barato de mantener.

2. Qué es un montículo

Un montículo de máximos (max-heap) es un árbol binario con dos reglas:

  1. Forma: es completo. Se llena por niveles, de izquierda a derecha, sin huecos. Solo el último nivel puede estar a medias.
  2. Orden: cada padre es >= que sus hijos. Por eso el máximo está en la raíz.

Fíjate en lo que no pide: entre hermanos no hay orden, y el hijo izquierdo puede ser mayor o menor que el derecho. No es un árbol de búsqueda (lección 5.2): no sirve para buscar un valor cualquiera.

Un montículo de mínimos es igual, con la regla al revés: cada padre <= que sus hijos, y el menor arriba.

«Montículo» no es «montón». En inglés las dos cosas se llaman heap, y por eso se confunden:

  • el montículo (heap, la estructura de datos) es esta forma de ordenar a medias que ves aquí;
  • el montón (heap, la memoria) es la zona donde viven las cosas creadas con new (lección 2.3).

No tienen nada que ver. En este curso siempre usamos la palabra justa.

3. El truco: el árbol cabe en un vector

Como el árbol es completo, no hacen falta nodos ni apuntadores. Se guarda por niveles en un vector<int> datos: la raíz en el 0, sus hijos en el 1 y el 2, los nietos del 3 al 6, y así.

Las flechas del árbol se calculan con aritmética. Para la posición i:

QuiénÍndiceEn el dibujo, para i = 1 (el 20)
padre(i - 1) / 2(1-1)/2 = 0 → el 30
hijo izquierdo2*i + 13 → el 5
hijo derecho2*i + 24 → el 10

La división es entera (lección 1.3): para i = 2, el padre es (2-1)/2 = 0. Un hijo existe solo si su índice es < datos.size().

class Monticulo {
private:
    vector<int> datos;            // el árbol, por niveles
    void subir(int i);             // sección 4
    void hundir(int i);            // sección 5
public:
    void insertar(int valor);
    int  extraerMax();
    int  verMax() const { return datos[0]; }   // O(1): está en la raíz
    bool vacia() const { return datos.empty(); }
    int  tamano() const { return (int)datos.size(); }
};

4. Insertar: entrar por abajo y subir

El nuevo entra al final del vector (así el árbol sigue completo). Luego sube: mientras sea mayor que su padre, se intercambian.

void insertar(int valor) {
    datos.push_back(valor);
    subir(tamano() - 1);
}

void subir(int i) {
    while (i > 0) {
        int padre = (i - 1) / 2;
        if (datos[i] <= datos[padre]) break;   // ya está en su sitio
        swap(datos[i], datos[padre]);
        i = padre;                              // sigue desde arriba
    }
}

5. Extraer el máximo: el último a la raíz y hundir

El máximo está en datos[0]. Para quitarlo sin dejar un hueco:

  1. guarda datos[0] para devolverlo;
  2. pon el último en la raíz y haz pop_back() (el árbol sigue completo);
  3. ese elemento suele ser pequeño: húndelo. Mientras algún hijo sea mayor, cámbialo con el mayor de sus hijos.
int extraerMax() {
    if (vacia()) throw out_of_range("montículo vacío");   // lección 4.4
    int maximo = datos[0];
    datos[0] = datos.back();
    datos.pop_back();
    if (!vacia()) hundir(0);
    return maximo;
}

void hundir(int i) {
    int n = tamano();
    while (true) {
        int izq = 2 * i + 1, der = 2 * i + 2, mayor = i;
        if (izq < n && datos[izq] > datos[mayor]) mayor = izq;
        if (der < n && datos[der] > datos[mayor]) mayor = der;
        if (mayor == i) break;                  // ningún hijo es mayor
        swap(datos[i], datos[mayor]);
        i = mayor;                              // sigue desde abajo
    }
}

Error típico al hundir: cambiar con el primer hijo mayor, no con el MAYOR. Con 25 arriba e hijos 20 y 28, si comparas solo con el izquierdo no cambias nada y el 28 queda debajo del 25: el montículo se rompe. Y el otro clásico: no comprobar izq < n antes de leer datos[izq] (fuera de rango, comportamiento indefinido).

6. ¿Por qué O(log n)?

Subir y hundir recorren un camino de la raíz a una hoja, nunca el árbol entero. Y como el árbol es completo, su altura es más o menos log2(n):

ElementosNiveles (como mucho)
73
1.00010
1.000.00020

Con un millón de datos, insertar o extraer son unos 20 intercambios como mucho. Buscar el máximo en un vector sin ordenar serían un millón de comparaciones.

7. std::priority_queue: el montículo ya hecho

En la práctica no escribes tu montículo: usas std::priority_queue de <queue>. Por dentro es un montículo sobre un vector, y por defecto arriba está el mayor (cppreference).

#include <queue>

priority_queue<int> pq;           // de máximos
pq.push(3); pq.push(9); pq.push(1); pq.push(7);
while (!pq.empty()) {
    cout << pq.top() << " ";      // mira el de arriba
    pq.pop();                      // lo quita
}
// Muestra: 9 7 3 1

Para un montículo de mínimos, se pasa greater<int> (de <functional>). La línea es larga; cópiala tal cual:

priority_queue<int, vector<int>, greater<int>> pq;   // de mínimos
// con los mismos push, muestra: 1 3 7 9
Tu Monticulopriority_queueCoste
insertar(x)push(x)O(log n)

extraerMax()top() y luego pop()O(log n)

pop() no devuelve nada. Igual que en std::stack y std::queue (lección 3.9):

int x = pq.pop();   // NO compila: «void value not ignored»
int x = pq.top();   // bien: primero mira...
pq.pop();           // ...y luego quita

Y top() o pop() sobre una cola vacía es comportamiento indefinido: pregunta antes empty().

Un uso típico: los k mayores

Para quedarte con los 3 mayores de un millón de datos no hace falta ordenar el millón. Usa una cola de mínimos con como mucho 3 elementos: mete cada dato y, si pasa de 3, saca el más pequeño. Al final quedan los 3 mayores. Cuesta O(n log k). Lo harás en el miniproyecto.

8. Heapsort: ordenar con un montículo

Si metes todo en un montículo y sacas el máximo una y otra vez, salen de mayor a menor. Ya es un algoritmo de ordenamiento, O(n log n):

Monticulo m;
for (int x : v) m.insertar(x);
for (int i = (int)v.size() - 1; i >= 0; i--)
    v[i] = m.extraerMax();         // el mayor al final, el siguiente antes...

El heapsort de verdad hace lo mismo sin vector extra, dentro del propio v:

  1. convierte v en montículo: hunde cada posición desde la mitad hacia atrás;
  2. repite: cambia la raíz (el mayor) con el último de la zona «viva», encoge la zona en uno y hunde la raíz.

Traza con v = 4 10 3 5 1. La barra | separa la zona viva (izquierda) de lo ya ordenado (derecha).

La biblioteca estándar trae las dos fases hechas, en <algorithm>:

vector<int> v = {4, 10, 3, 5, 1};
make_heap(v.begin(), v.end());   // fase 1: ahora v es un montículo (el 10 delante)
sort_heap(v.begin(), v.end());   // fase 2: v = 1 3 4 5 10

Heapsort es O(n log n) siempre, incluso en el peor caso, y no usa memoria extra. A cambio no es estable: lo verás en la lección 5.5, junto a los demás algoritmos de ordenamiento.

¿Qué pasa en la memoria?

Un Monticulo no tiene nodos ni apuntadores: es un único vector<int>. Si declaras Monticulo m; en main, el objeto pequeño del vector vive en el marco de main, en la memoria automática (la pila de llamadas o stack). Sus números van seguidos en el montón (heap). Sí: el montículo guarda sus datos en el montón, pero son dos ideas distintas que comparten nombre en inglés.

«padre» e «hijo» = cuentas con índices

Ir al padre o a un hijo es una cuenta, no seguir una flecha. Y push_back puede mudar los datos a un bloque más grande cuando se llena la capacidad: el vector es su dueño y lo libera solo. priority_queue hace lo mismo con su vector interno.
