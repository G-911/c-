1. De la lista al árbol

Un árbol binario es un montón de nodos donde cada uno apunta, como mucho, a dos hijos: uno a la izquierda y otro a la derecha. «Binario» quiere decir solo eso: dos hijos como máximo.

struct NodoArbol {
    int dato;
    NodoArbol* izq;      // hijo izquierdo (o nullptr)
    NodoArbol* der;      // hijo derecho  (o nullptr)

    NodoArbol(int d) : dato(d), izq(nullptr), der(nullptr) {}   // nace sin hijos
};

Los árboles de informática se dibujan al revés: la raíz arriba y las hojas abajo.

Dos formas de contar la altura. En este curso contamos nodos: árbol vacío = 0, un solo nodo = 1. Algunos libros cuentan flechas y les sale uno menos (vacío = −1, un nodo = 0). Las dos valen; lo que no vale es mezclarlas. Si en un examen te piden la altura, mira qué definición usan.

3. Construir un árbol a mano

Igual que encadenabas nodos en la lista, aquí enganchas hijos:

NodoArbol* raiz = new NodoArbol(8);
raiz->izq = new NodoArbol(3);
raiz->der = new NodoArbol(10);
raiz->izq->izq = new NodoArbol(1);      // el hijo izquierdo del 3
raiz->izq->der = new NodoArbol(6);      // el hijo derecho del 3
raiz->der->der = new NodoArbol(14);     // el 10 no tiene hijo izquierdo

Es el árbol de los dibujos. Lo vamos a usar en toda la lección.

4. Un árbol es una definición recursiva

Esta es la idea que lo hace todo fácil. Un árbol es una de dos cosas:

  • o está vacío (nullptr),
  • o es un nodo con un árbol a su izquierda y otro árbol a su derecha.

Cada hijo es, él mismo, un árbol más pequeño. Por eso casi todas las funciones de árboles tienen la misma forma (Stanford CS106B, Trees):

tipo funcion(NodoArbol* n) {
    if (n == nullptr) return ...;     // caso base: árbol vacío
    ... funcion(n->izq) ...           // resolver la izquierda
    ... funcion(n->der) ...           // resolver la derecha
    ... combinar con n->dato ...
}

Con una lista podías elegir entre un while y la recursión. Con un árbol el while no basta: en cada nodo hay dos caminos y hay que recorrer los dos.

5. Los tres recorridos

Recorrer = visitar todos los nodos una vez. Solo cambia cuándo se visita la raíz respecto de sus dos subárboles. Guardamos lo visitado en un vector<int> (pasado por referencia, lección 2.1):

Preorden: raíz, izquierda, derecha

void preorden(NodoArbol* n, vector<int>& salida) {
    if (n == nullptr) return;
    salida.push_back(n->dato);      // 1.º la raíz
    preorden(n->izq, salida);       // 2.º todo el lado izquierdo
    preorden(n->der, salida);       // 3.º todo el lado derecho
}

Inorden: izquierda, raíz, derecha

void inorden(NodoArbol* n, vector<int>& salida) {
    if (n == nullptr) return;
    inorden(n->izq, salida);
    salida.push_back(n->dato);      // la raíz, en medio
    inorden(n->der, salida);
}

¿Te fijas? Salió ordenado. No es casualidad: este árbol cumple una regla especial (los menores a la izquierda, los mayores a la derecha). Es el árbol de búsqueda de la próxima lección.

Postorden: izquierda, derecha, raíz

void postorden(NodoArbol* n, vector<int>& salida) {
    if (n == nullptr) return;
    postorden(n->izq, salida);
    postorden(n->der, salida);
    salida.push_back(n->dato);      // la raíz, al final
}

Truco para no confundirlos: el nombre dice dónde va la raíz. Pre = antes, in = en medio, post = después. Los dos subárboles van siempre izquierda primero.

6. Contar nodos y medir la altura

La misma plantilla de la sección 4, combinando de otra forma:

int contarNodos(NodoArbol* n) {
    if (n == nullptr) return 0;                              // vacío: 0 nodos
    return 1 + contarNodos(n->izq) + contarNodos(n->der);   // yo + los de cada lado
}

int altura(NodoArbol* n) {
    if (n == nullptr) return 0;                              // vacío: altura 0
    return 1 + max(altura(n->izq), altura(n->der));         // mi nivel + el lado más alto
}
// Con el árbol de la lección: contarNodos(raiz) == 6, altura(raiz) == 3

max viene de <algorithm>. Léelo como una frase: «la altura de un árbol es uno más la altura de su subárbol más alto».

Error típico: olvidar el caso base.

int contarNodos(NodoArbol* n) {
    return 1 + contarNodos(n->izq) + contarNodos(n->der);   // ¿y si n es nullptr?
}

Al llegar debajo de una hoja, n vale nullptr y n->izq lo desreferencia: el programa se cae. Toda función recursiva de árboles empieza con if (n == nullptr).

8. Liberar el árbol: en postorden

Cada nodo se creó con new; cada uno necesita su delete. La pregunta es en qué orden. Respuesta: primero los hijos, el padre al final. Es decir, postorden:

void liberar(NodoArbol* n) {
    if (n == nullptr) return;
    liberar(n->izq);      // 1. todo lo de la izquierda
    liberar(n->der);      // 2. todo lo de la derecha
    delete n;             // 3. ahora sí, este nodo
}

Error típico: borrar primero el padre.

delete n;
liberar(n->izq);      // ¡n ya no existe!
liberar(n->der);

Las direcciones de los hijos estaban dentro del nodo que acabas de liberar. Leer n->izq después del delete es usar un apuntador colgante (lección 2.3): a veces «funciona», a veces se cae. Es el mismo error que en el destructor de la lista, y por la misma razón. Con -fsanitize=address lo verías como heap-use-after-free.

¿Qué pasa en la memoria?

Los seis nodos viven en el montón (heap), cada uno donde le tocó: cada new NodoArbol pide una caja de sizeof(NodoArbol) bytes (normalmente 24: un int, dos apuntadores y relleno). En el marco de main, en la memoria automática (la pila de llamadas o stack; no es la clase Pila del Nivel 3), solo está raiz. Cada llamada recursiva apila un marco con su propia copia de n; cuando hace return, se libera sola. Las direcciones son inventadas:

Fíjate en lo importante: a la vez nunca hay más marcos que altura + 1 (el +1 es la llamada con nullptr), no uno por nodo. En un árbol repartido de un millón de nodos eso son una veintena de marcos. En una cadena de un millón, un millón de marcos: la pila de llamadas puede desbordarse. Y el dueño de los nodos es quien guarda raiz: si ese apuntador muere sin liberar, todo el árbol se queda en el montón (fuga de memoria).
