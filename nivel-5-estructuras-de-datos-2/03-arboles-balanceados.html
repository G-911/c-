Árboles balanceados (AVL)

Un árbol de búsqueda que se endereza solo con rotaciones. ~40 minutos.

Al terminar podrás: calcular el factor de balance de un nodo, reconocer los cuatro casos de desequilibrio, arreglarlos con rotaciones simples y dobles, e insertar en un árbol AVL que nunca degenera en lista.

Antes de empezar: repite sin mirar el quiz de la lección 5.2 (árbol binario de búsqueda). Esta lección se apoya en insertarEn de allí: tenlo fresco.

Por qué. La lección 5.2 terminó con un problema: si insertas datos ordenados, el árbol de búsqueda se vuelve una lista y todo cuesta O(n). Un árbol balanceado se reorganiza solo al insertar para que su altura se quede siempre cerca de log₂(n). El AVL (por sus inventores, Adelson-Velsky y Landis, 1962) fue el primero (Wikipedia, AVL tree). Las rotaciones que vas a ver aquí son la pieza común de casi todos los árboles balanceados, incluido el que usa std::map.

1. Qué significa «balanceado»

Los mismos cinco datos pueden formar una cadena o un árbol bajo. La regla del AVL dice cuándo un árbol es «suficientemente bajo»: en cada nodo, las alturas de sus dos subárboles se diferencian como mucho en 1.

Para medirlo se usa el factor de balance de cada nodo:

factor de balance = altura(subárbol izquierdo) − altura(subárbol derecho)
  • +1, 0 o −1: el nodo está bien.
  • +2: cargado a la izquierda. −2: cargado a la derecha. Hay que arreglarlo.

A la derecha, el 10 tiene a la izquierda un subárbol vacío (altura 0) y a la derecha uno de altura 2 (14 y 15): 0 − 2 = −2. Al 8 no le pasa nada: 2 − 3 = −1. El problema siempre aparece en algún nodo del camino por el que bajó la inserción.

2. El nodo guarda su altura

Calcular la altura recorriendo todo el subárbol (como en la 5.1) es O(n): demasiado caro para hacerlo en cada nodo. El AVL la guarda dentro del nodo y la recalcula a partir de la de sus hijos, que ya está al día:

struct NodoAVL {          // el NodoArbol de siempre, con un campo más
    int dato;
    NodoAVL* izq;
    NodoAVL* der;
    int altura;           // una hoja mide 1
    NodoAVL(int d) : dato(d), izq(nullptr), der(nullptr), altura(1) {}
};

int altura(NodoAVL* n) { return n == nullptr ? 0 : n->altura; }   // vacío: 0

void actualizarAltura(NodoAVL* n) {
    n->altura = 1 + max(altura(n->izq), altura(n->der));        // O(1), no recorre nada
}

int factorBalance(NodoAVL* n) {
    return n == nullptr ? 0 : altura(n->izq) - altura(n->der);
}

3. Rotación a la derecha (caso izquierda-izquierda)

Inserta 30, 20, 10 en ese orden. El 30 queda con +2 y su hijo, el 20, con +1: los dos cargados a la izquierda. El arreglo es subir el 20:

Eso es una rotación a la derecha sobre el 30. En general, con subárboles cualesquiera colgando (los triángulos), queda así. Lo que cambia, en color:

NodoAVL* rotarDerecha(NodoAVL* y) {
    NodoAVL* x = y->izq;       // x va a subir
    NodoAVL* t2 = x->der;      // el subárbol del medio
    x->der = y;                // y baja a la derecha de x
    y->izq = t2;               // t2 cambia de padre
    actualizarAltura(y);       // primero y: ahora está DEBAJO de x
    actualizarAltura(x);
    return x;                  // la nueva raíz de este subárbol
}

La clave: el orden no se rompe. Lee los dos dibujos en inorden: antes T1 x T2 y T3; después T1 x T2 y T3. Lo mismo. T2 era mayor que x y menor que y, y sigue en un sitio donde eso se cumple. Una rotación cambia la forma, nunca el orden.

Son solo dos asignaciones de apuntadores (más la tercera, la del padre, que hace quien recibe el return). No se crea ni se borra ningún nodo.

4. Rotación a la izquierda (caso derecha-derecha)

Es el espejo. Inserta 10, 20, 30: el 10 queda con −2 y el 20 con −1, cargados a la derecha. Sube el 20 por el otro lado:

NodoAVL* rotarIzquierda(NodoAVL* x) {
    NodoAVL* y = x->der;
    NodoAVL* t2 = y->izq;
    y->izq = x;
    x->der = t2;
    actualizarAltura(x);       // primero el que bajó
    actualizarAltura(y);
    return y;
}

Error típico: actualizar las alturas al revés. Si en rotarDerecha haces actualizarAltura(x) antes que la de y, x calcula su altura con la altura vieja de y (la de cuando y estaba arriba). Con 30, 20, 10 el 20 queda diciendo que mide 4 cuando mide 2, y todos los factores de balance de encima salen mal. Regla: primero el que bajó, después el que subió.

7. Los cuatro casos en una tabla, y en código

CasoNodoHijo de ese ladoArreglo
izquierda-izquierda+2+1 o 0rotar a la derecha el nodo
derecha-derecha−2−1 o 0rotar a la izquierda el nodo
izquierda-derecha+2−1a la izquierda el hijo, luego a la derecha el nodo
derecha-izquierda−2+1a la derecha el hijo, luego a la izquierda el nodo

Truco: si el nodo y su hijo se inclinan al mismo lado, una rotación; si se inclinan a lados opuestos (zigzag), dos. Todo cabe en una función:

NodoAVL* balancear(NodoAVL* n) {
    actualizarAltura(n);
    int fb = factorBalance(n);
    if (fb > 1) {                              // cargado a la izquierda
        if (factorBalance(n->izq) < 0)         // zigzag: izquierda-derecha
            n->izq = rotarIzquierda(n->izq);   // ahora es izquierda-izquierda
        return rotarDerecha(n);
    }
    if (fb < -1) {                             // cargado a la derecha
        if (factorBalance(n->der) > 0)         // zigzag: derecha-izquierda
            n->der = rotarDerecha(n->der);
        return rotarIzquierda(n);
    }
    return n;                                  // ya estaba bien
}

8. Insertar en un AVL

Aquí se nota el patrón de la lección 5.2. Es el mismo insertarEn, con un solo cambio en la última línea:

NodoAVL* insertarEn(NodoAVL* n, int valor) {
    if (n == nullptr) return new NodoAVL(valor);
    if (valor < n->dato) n->izq = insertarEn(n->izq, valor);
    else                 n->der = insertarEn(n->der, valor);
    return balancear(n);       // antes era: return n;
}

La recursión baja hasta el hueco, crea el nodo y, al volver, cada nodo del camino actualiza su altura y se arregla si hace falta. Como el ayudante devuelve la raíz del subárbol, el padre recibe automáticamente la nueva raíz tras una rotación. Por eso en la 5.2 te insistí con ese patrón.

Mira el AVL recibiendo 1, 2, 3, 4, 5, 6, 7 en orden, lo que destrozaba al árbol de la 5.2:

Fíjate en el segundo: tras insertar el 5, tanto el 3 como el 2 quedan con −2. Pero la recursión arregla de abajo arriba: el 3 se arregla primero y, al hacerlo, el 2 vuelve a −1. Basta una rotación. Al final, siete datos ordenados forman un árbol perfecto de altura 3.

Error típico: rotar y no usar lo que devuelve.

if (fb > 1) rotarDerecha(n);     // el resultado se tira
return n;                        // pero n ya NO es la raíz del subárbol

Tras la rotación, n ha bajado. El padre sigue apuntando a n, y el nodo que subió (con todo su lado izquierdo) se queda sin nadie que lo apunte: se pierde del árbol y se fuga. Con 30, 20, 10, el árbol se queda solo con el 30. Siempre return rotarDerecha(n); o n->izq = rotarIzquierda(n->izq);.

9. ¿Cuánto mide un AVL?

Se demuestra que la altura de un AVL con n nodos nunca pasa de aproximadamente 1,44 · log₂(n) (Wikipedia, AVL tree): en el peor caso, un 44 % más que el árbol perfecto. Así que buscar, insertar y borrar son O(log n) siempre, sin importar el orden de los datos.

10. ¿Y la biblioteca estándar?

std::map y std::set (lección 4.2) son árboles de búsqueda balanceados. cppreference dice que «normalmente se implementan como árboles rojo-negro» (usually implemented as red-black trees, std::map, std::set). El rojo-negro es otro árbol balanceado: también rota, pero su regla es menos estricta que la del AVL, así que puede quedar algo más alto (el AVL es más rígido y por eso busca un poco más rápido, según la misma página de Wikipedia). Lo importante para ti: por eso map garantiza O(log n), y por eso un map recorrido con un for sale ordenado: es un inorden.

En la práctica, usa std::map/std::set. Programar un AVL es para entender cómo funcionan por dentro y para el examen.

¿Qué pasa en la memoria?

Una rotación no mueve, copia ni crea nada en el montón: los nodos siguen en las mismas direcciones y solo cambian tres apuntadores (dos dentro de los nodos y el del padre, que se reasigna con el return). Por eso cuesta O(1) y por eso nodosVivos no cambia en el miniproyecto. Con direcciones inventadas, rotarDerecha sobre 30, 20, 10:

             30 (0x100).izq    20 (0x200).der    el padre apunta a
antes:       0x200             nullptr           0x100
después:     nullptr           0x100             0x200

Si un apuntador se queda sin reasignar (el error de la sección 8), un nodo pierde a su único dueño: se fuga. Lo que sí cuesta memoria es el campo nuevo: sizeof(NodoAVL) da normalmente 32 frente a los 24 de NodoArbol (un int más y relleno; compruébalo con sizeof). A cambio, la recursión de insertarEn nunca apila más de unos 1,44·log₂(n) marcos.
