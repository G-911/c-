Árbol binario de búsqueda

Menores a la izquierda, mayores a la derecha: buscar sin mirarlo todo. ~40 minutos.

Al terminar podrás: escribir una clase ArbolBusqueda que inserta, busca, da el mínimo y el máximo, elimina en los tres casos (hoja, un hijo, dos hijos) y se libera sola; y explicar por qué a veces es tan lenta como una lista.

Antes de empezar: repite sin mirar el quiz de la lección 5.1 (árboles binarios).

Por qué. En la lección 3.8 viste que la búsqueda binaria en un vector ordenado es O(log n), pero meter un dato en medio obliga a correr todos los demás: O(n). El árbol binario de búsqueda (en inglés binary search tree, BST) hace las dos cosas en O(log n)… cuando está bien repartido. Es la pieza de exámenes universitarios por excelencia, y la idea que hay debajo de std::map y std::set.

1. La regla del árbol de búsqueda

Un árbol binario es de búsqueda si, para cada nodo:

  • todo lo que hay en su subárbol izquierdo es menor que él, y
  • todo lo que hay en su subárbol derecho es mayor.

En este curso no admitimos repetidos: insertar un valor que ya está no hace nada.

Error típico: comprobar solo con el padre. En el árbol de la derecha, el 9 es mayor que su padre 3, así que «está bien puesto» respecto al 3. Pero está en el subárbol izquierdo del 8, y 9 > 8. La regla habla de todo el subárbol, no solo del padre. Si alguien busca el 9, irá a la derecha del 8 y nunca lo encontrará.

2. La clase

Igual que ListaEnlazada solo guardaba cabeza, el árbol solo guarda raiz. Los métodos públicos llaman a ayudantes privados recursivos que reciben un nodo:

class ArbolBusqueda {
private:
    NodoArbol* raiz;                                 // nullptr = árbol vacío
    NodoArbol* insertarEn(NodoArbol* n, int valor);  // ayudantes recursivos
    NodoArbol* eliminarEn(NodoArbol* n, int valor);
    void liberar(NodoArbol* n);
public:
    ArbolBusqueda() : raiz(nullptr) {}
    ~ArbolBusqueda() { liberar(raiz); }             // el liberar de la 5.1
    ArbolBusqueda(const ArbolBusqueda&) = delete;             // prohibido copiar:
    ArbolBusqueda& operator=(const ArbolBusqueda&) = delete;  // evita la doble liberación (lección 3.5)
    bool insertar(int valor);
    bool buscar(int valor) const;
    int minimo() const;
    int maximo() const;
    bool eliminar(int valor);
    // altura, tamano e inorden: los de la lección 5.1
};

Las dos líneas con = delete dicen «esta clase no se copia». Así el compilador rechaza ArbolBusqueda b = a; en lugar de dejar dos árboles con los mismos nodos.

3. Buscar: decidir en cada nodo

Para buscar el 6 no hace falta mirarlo todo. En cada nodo, una comparación dice hacia qué lado seguir, y el otro lado entero se descarta:

bool buscar(int valor) const {
    NodoArbol* actual = raiz;
    while (actual != nullptr) {
        if (valor == actual->dato) return true;     // encontrado
        if (valor < actual->dato) actual = actual->izq;   // menor: a la izquierda
        else                      actual = actual->der;   // mayor: a la derecha
    }
    return false;                                   // llegó a nullptr: no está
}

Aquí basta un while, sin recursión: solo se baja por un camino. Cuantas comparaciones hagas depende de la altura, no del número de nodos.

4. Insertar: buscar el hueco

Insertar es buscar el valor hasta caer en un nullptr. Ese hueco es justo donde tiene que ir. El truco elegante: el ayudante devuelve la raíz del subárbol, y cada padre se la reasigna a su hijo.

NodoArbol* insertarEn(NodoArbol* n, int valor) {
    if (n == nullptr) return new NodoArbol(valor);      // el hueco: aquí va
    if (valor < n->dato) n->izq = insertarEn(n->izq, valor);
    else                 n->der = insertarEn(n->der, valor);
    return n;                                            // este subárbol sigue empezando en n
}

bool insertar(int valor) {
    if (buscar(valor)) return false;      // sin repetidos
    raiz = insertarEn(raiz, valor);       // funciona también con el árbol vacío
    return true;
}

¿Por qué devolver la raíz? Porque con el árbol vacío la raíz cambia (de nullptr al nodo nuevo), y con este patrón no hace falta un caso especial. En la lección 5.3 lo vas a agradecer: las rotaciones también cambian la raíz de un subárbol.

5. Mínimo y máximo

El más pequeño está lo más a la izquierda posible; el más grande, lo más a la derecha.

int minimo() const {
    if (raiz == nullptr) throw out_of_range("minimo: el árbol está vacío");   // lección 4.4
    NodoArbol* actual = raiz;
    while (actual->izq != nullptr) actual = actual->izq;     // parar EN el último
    return actual->dato;
}
// maximo(): igual, con der.

Fíjate en la condición: actual->izq != nullptr se detiene en el último nodo, no después. Y con el árbol vacío no hay ningún valor sensato que devolver: se lanza una excepción, como hacía pop() en la Pila de la lección 4.4.

6. Inorden = ordenado

El inorden visita izquierda, raíz, derecha. Por la regla del árbol, todo lo de la izquierda es menor y todo lo de la derecha es mayor; y eso vale en cada subárbol. Resultado: el inorden de un árbol de búsqueda sale siempre ordenado de menor a mayor. Con el árbol de arriba: 1 3 4 6 7 8 10 14.

Eso da un método de ordenar «gratis»: mete los datos en el árbol y sácalos en inorden.

7. Eliminar: los tres casos

Es la operación difícil (Stanford CS106B la llama «hard function»). Primero se busca el nodo bajando igual que al insertar. Al encontrarlo, depende de cuántos hijos tenga.

Caso 1: es una hoja

Se libera y su padre pasa a apuntar a nullptr.

Caso 2: tiene un solo hijo

El hijo sube a ocupar su sitio: el padre pasa a apuntar al nieto. Todo lo que colgaba del hijo viene con él.

Caso 3: tiene dos hijos

Aquí no se puede «subir» a un hijo: ¿cuál? ¿Y qué hacemos con el otro? El truco es buscar un sustituto que mantenga la regla: el sucesor inorden, que es el mínimo del subárbol derecho (el siguiente en orden). Se copia su dato en el nodo, y luego se elimina el sucesor original, que es fácil: nunca tiene hijo izquierdo (si lo tuviera, ese sería el mínimo), así que es el caso 1 o el 2.

El 4 sirve porque es mayor que todo lo de la izquierda (es mayor que 3) y menor que todo lo demás de la derecha (es el mínimo de ese lado).

El código

NodoArbol* eliminarEn(NodoArbol* n, int valor) {
    if (n == nullptr) return nullptr;
    if (valor < n->dato) { n->izq = eliminarEn(n->izq, valor); return n; }
    if (valor > n->dato) { n->der = eliminarEn(n->der, valor); return n; }

    // Encontrado: n es el que se va.
    if (n->izq == nullptr) {                 // casos 1 y 2: hoja o solo hijo derecho
        NodoArbol* hijo = n->der;            // guardar ANTES del delete
        delete n;
        return hijo;                         // el hijo (o nullptr) ocupa su sitio
    }
    if (n->der == nullptr) {                 // caso 2: solo hijo izquierdo
        NodoArbol* hijo = n->izq;
        delete n;
        return hijo;
    }
    NodoArbol* sucesor = n->der;             // caso 3: dos hijos
    while (sucesor->izq != nullptr) sucesor = sucesor->izq;
    n->dato = sucesor->dato;                         // copiar el dato
    n->der = eliminarEn(n->der, sucesor->dato);      // borrar el original
    return n;
}

bool eliminar(int valor) {
    if (!buscar(valor)) return false;
    raiz = eliminarEn(raiz, valor);          // la raíz puede cambiar
    return true;
}

Mira el primer if del «encontrado»: cubre la hoja y el nodo con solo hijo derecho, porque en una hoja n->der ya es nullptr. Es el mismo patrón «devuelvo la nueva raíz del subárbol» de insertar.

Error típico: borrar un nodo con dos hijos «a lo bruto».

delete n;
return nullptr;      // ¿y sus dos subárboles?

El padre pasa a apuntar a nullptr y todos los nodos de debajo quedan sin nadie que los apunte: perdidos para el árbol y sin liberar (fuga de memoria). El otro clásico es copiar el dato del sucesor y olvidar borrar el original: el valor queda repetido.

8. El problema: el árbol degenerado

Todas las operaciones bajan por un camino, así que cuestan O(altura). Si el árbol está repartido, la altura es más o menos log₂(n): con 1000 nodos, unos 10 niveles. Pero mira qué pasa al insertar datos ya ordenados:

Cada valor es mayor que todos los anteriores, así que siempre va a la derecha. El árbol degenera en una lista: altura n, y buscar vuelve a ser O(n).

Y los datos ordenados son lo más normal del mundo (IDs, fechas, listas exportadas). La solución es que el árbol se reorganice solo al insertar: eso es la lección 5.3.

¿Qué pasa en la memoria?

Tu ArbolBusqueda a; en main vive en la memoria automática (la pila de llamadas o stack) y es diminuto: solo guarda raiz (sizeof(a) da normalmente 8). Los nodos están en el montón, y el árbol es su dueño: por eso su destructor llama a liberar y por eso prohibimos copiarlo. Al eliminar con dos hijos no se mueve ningún nodo: cambia un número y se libera otra caja. Con direcciones inventadas:

a (marco de main)
raiz = 0x100
no cambia: el 8 sigue arriba
nodo 0x200
dato: 3 → 4
la misma caja, otro dato
nodo 0x500
dato: 4
esta es la del delete

Y la recursión cuesta memoria automática: insertarEn y eliminarEn apilan un marco por nivel. En el árbol degenerado, insertar 100 000 valores ordenados pide 100 000 marcos a la vez, y la pila de llamadas puede desbordarse. Un árbol balanceado lo deja en unos 17.
