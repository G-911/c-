STL: contenedores

Diccionarios, conjuntos e iteradores: buscar por clave en vez de recorrer. ~35 minutos.

Al terminar podrás: contar cuántas veces aparece cada palabra con un map, quitar repetidos con un set, buscar sin romper nada con find, y elegir el contenedor adecuado para cada problema.

Por qué. En la 3.8 viste que buscar en un vector o en una lista es O(n): hay que mirar uno por uno. Muchos problemas reales son «dame el dato de esta clave»: el nombre de un carnet, el precio de un producto, cuántas veces salió una palabra. Para eso la STL (Standard Template Library, la parte de plantillas de la biblioteca estándar) trae contenedores que buscan por clave sin recorrer todo. Ahora que conoces las plantillas (4.1), los <> ya no tienen misterio.

Calentamiento (3 minutos). Antes de empezar, repite sin mirar el quiz de la lección 4.1.

1. pair: dos datos juntos

Un pair guarda dos valores, que pueden ser de tipos distintos. Se leen con .first y .second. Está en <utility>:

#include <utility>

pair<string, int> p = {"Ana", 20};
cout << p.first;    // Ana
cout << p.second;   // 20
p.second = 21;      // se puede cambiar

Sirve para que una función devuelva dos cosas (en el miniproyecto, una palabra y cuántas veces salió). Y, sobre todo, es la pieza con la que está hecho un map.

2. map: un diccionario ordenado

Un map<Clave, Valor> guarda parejas clave → valor. Cada clave aparece una sola vez, y el map las mantiene ordenadas por clave. Buscar, insertar y borrar cuestan O(log n) (cppreference, std::map).

#include <map>

map<string, int> edades;
edades["Luis"] = 31;     // no existía: la crea
edades["Ana"]  = 20;
edades["Luis"] = 32;     // ya existía: la cambia (no se duplica)
cout << edades.size();   // 2
cout << edades["Ana"];   // 20

Recorrer un map

Cada elemento de un map es un pair: .first es la clave y .second el valor. Se recorre con el for de rango de siempre, y sale ordenado por clave, no en el orden en que metiste los datos:

for (const auto& par : edades) {
    cout << par.first << " tiene " << par.second << "\n";
}
// Ana tiene 20
// Luis tiene 32

Desde C++17 puedes ponerle nombre a las dos mitades directamente. Es lo mismo, pero se lee mejor:

for (const auto& [nombre, edad] : edades) {
    cout << nombre << " tiene " << edad << "\n";
}

La clave no se puede cambiar mientras recorres (es const: si la cambiaras, el orden se rompería). El valor sí, si recorres con auto& sin const.

3. Buscar sin crear

m[clave] es cómodo, pero tiene una trampa: si la clave no existe, la crea con el valor por defecto (0 para int, "" para string) (cppreference, operator[]). Para solo preguntar, usa una de estas:

if (edades.count("Pedro") == 1) { ... }   // count: 1 si está, 0 si no

auto it = edades.find("Pedro");           // find: un iterador (sección 4)
if (it != edades.end()) {
    cout << it->second;                   // solo aquí es seguro leerlo
}

cout << edades.at("Ana");                 // at: si no está, lanza una excepción (lección 4.4)

Error típico: preguntar con [].

if (edades["Pedro"] == 0) cout << "Pedro no está";

Funciona… y de paso mete a Pedro en el map con edad 0. Ahora size() creció y Pedro sale al recorrer. Además, si el map es const (por ejemplo, un parámetro const map<...>&), [] ni siquiera compila, porque modifica. Para preguntar: count o find.

4. Iteradores: el «apuntador» de los contenedores

Un iterador señala un elemento dentro de un contenedor. Se usa casi como un apuntador (2.2): *it es el elemento, it-> entra en él, y ++it pasa al siguiente. Todo contenedor tiene dos:

  • begin(): señala el primer elemento.
  • end(): señala uno después del último. No es un elemento: no se desreferencia nunca. Es como el nullptr al final de tu lista enlazada: la marca de «se acabó».
"Ana" → 20
↑ begin()
"Beto" → 25
↑ ++it
"Luis" → 32
último
(nada)
↑ end(): no se toca

El for de rango de la sección 2 es, por dentro, este bucle:

for (auto it = edades.begin(); it != edades.end(); ++it) {
    cout << it->first << " " << it->second << "\n";   // como nodo->dato
}

Y por eso find devuelve un iterador: si encontró, señala el elemento; si no, devuelve end(). Siempre compara con end() antes de usarlo. Lo mismo vale para vector, list y set: begin y end son el idioma común de la STL, y en la 4.3 los algoritmos se alimentan de ellos.

5. unordered_map: más rápido, sin orden

Misma forma de uso que map ([], find, count, at, recorrer), pero por dentro usa una tabla hash. Buscar, insertar y borrar cuestan O(1) en promedio, y a cambio no hay orden: al recorrer, los elementos salen en un orden arbitrario (cppreference, std::unordered_map).

#include <unordered_map>

unordered_map<int, string> carnets;
carnets[12345678] = "Ana";
carnets[87654321] = "Luis";
cout << carnets[12345678];    // Ana

Regla rápida: ¿necesitas recorrer en orden? map. ¿Solo buscar por clave? unordered_map.

6. set: un conjunto sin repetidos

Un set es como un map con solo claves: guarda valores únicos y ordenados. Si insertas uno que ya está, no pasa nada.

#include <set>

set<int> s = {5, 1, 5, 3};     // se queda con {1, 3, 5}
s.insert(3);                    // ya estaba: no cambia
cout << s.size();               // 3
cout << s.count(5);             // 1 (está)
for (int x : s) cout << x;      // 135

insert devuelve un pair: .second es true si de verdad lo insertó y false si ya estaba (cppreference, set::insert). Así detectas repetidos en una línea: if (!vistos.insert(x).second) cout << "repetido";

Ante la duda, empieza por vector: es el más simple y suele ser el más rápido para pocos datos. Cambia cuando necesites buscar por clave.

¿Qué pasa en la memoria?

Un map o un set se parece a tu lista enlazada. El objeto edades es pequeño y vive en el marco de la función; cada pareja "Ana" → 20 va en su propio nodo del montón (heap), y los nodos se enlazan con apuntadores formando un árbol (normalmente un árbol rojo-negro). Por eso buscar es O(log n): baja por las ramas en vez de recorrerlo todo. El unordered_map carnets, en cambio, reparte sus elementos en cubetas (buckets) según el hash de la clave. En los dos casos el contenedor es el dueño: cuando muere, libera todos sus nodos.

Un iterador es, en el fondo, un apuntador con disfraz: señala un elemento. ¿Cuándo deja de valer? En map y set, insertar no invalida ninguno, y borrar solo invalida los que señalaban al elemento borrado: los nodos nunca se mudan. En unordered_map, si una inserción obliga a repartir de nuevo las cubetas (rehash), los iteradores dejan de valer, aunque las referencias a los elementos siguen bien. Y en vector, como viste en la 1.8, si push_back muda los datos, todo iterador viejo queda colgante.

Miniproyecto 4.2 · Contar, buscar y quitar repetidos

Abre ejercicios/02-stl-contenedores.cpp. Completa cuatro funciones cortas:

  1. contarPalabras: devuelve un map<string, int> con cuántas veces sale cada palabra.
  2. masFrecuente: recorre ese map y devuelve un pair con la palabra que más sale y sus veces.
  3. unicosOrdenados: quita los repetidos de un vector y lo ordena, usando un set.
  4. buscarEdad: busca en un unordered_map const sin usar []; devuelve -1 si no está.

Compílalo desde la carpeta ejercicios:

g++ -std=c++17 -Wall 02-stl-contenedores.cpp -o prog && ./prog

Al principio verás varias ✗. Terminaste cuando salgan todas en ✓. Unos 20 minutos.

Si te atascas: contarPalabras es una línea dentro del for: conteo[p]++ (aquí sí conviene que [] cree la clave con 0). Para unicosOrdenados, un set se puede crear directamente desde un rango: set<int> s(v.begin(), v.end());, y un vector igual desde el set. La solución está en soluciones/02-stl-contenedores.cpp; ábrela solo después de intentarlo de verdad.
