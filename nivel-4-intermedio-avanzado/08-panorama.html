Panorama: qué se hace con C++ y cómo seguir

El mapa de todo lo que hay más allá de este curso, y un proyecto final que lo junta todo. ~40 minutos.

Al terminar podrás: usar un depurador y los sanitizers para cazar errores, saber qué trajo cada estándar de C++, elegir una ruta según lo que te guste (juegos, embebidos, sistemas o programación competitiva) y escribir un programa completo con clases, STL, archivos y excepciones.

Antes de empezar: repite sin mirar el quiz de la lección 4.7 (semántica de movimiento). El hábito de repasar, quédatelo: lo seguirás usando en los Niveles 5 y 6.

Por qué. Ya sabes lo que pide la universidad (apuntadores, listas, pilas, colas con POO) y lo que se usa en un proyecto moderno (plantillas, STL, lambdas, excepciones, apuntadores inteligentes, movimiento). Esta lección no enseña un tema nuevo a fondo: te da el mapa. Qué se construye con C++, qué herramientas usan los profesionales y por dónde seguir según lo que te guste. Todas las afirmaciones llevan su enlace, para que puedas comprobarlas.

1. Dónde se usa C++ de verdad

C++ aparece donde importa la velocidad o el control del hardware. Bjarne Stroustrup, el creador del lenguaje, mantiene una lista (antigua, pero ilustrativa) de programas escritos total o mayormente en C++: navegadores como Chrome y Firefox, Microsoft Office, Photoshop, MySQL o el propio compilador GCC (Stroustrup — C++ Applications). 2. Concurrencia: varias cosas a la vez (solo una mención)

Desde C++11 el estándar trae std::thread para lanzar hilos: funciones que corren a la vez (cppreference — std::thread).

#include <thread>

void contar(const string& nombre) {
    for (int i = 1; i <= 3; i++) cout << nombre << " " << i << "\n";
}

int main() {
    thread t1(contar, "A");   // arranca contar("A") en otro hilo
    thread t2(contar, "B");
    t1.join();                // espera a que termine
    t2.join();
}

Una ejecución real de este programa mostró A B 1 en la primera línea: los dos hilos escribieron en cout a la vez y las salidas se mezclaron. Esa es la gran dificultad de la concurrencia: el orden ya no es predecible y, si dos hilos tocan el mismo dato sin protección (un mutex), el resultado es un error difícil de reproducir. Además, si un thread muere sin join() ni detach(), el programa se aborta con std::terminate() (cppreference — ~thread). Si te interesa, el libro de referencia es C++ Concurrency in Action, 2.ª ed., de Anthony Williams (cubre C++14 y C++17) (Manning).

3. Bibliotecas que vas a oír nombrar

  • Boost: colección de bibliotecas revisadas por la comunidad. Según su web, más de 40 de ellas acabaron entrando en el estándar de C++ (boost.org). Es un buen sitio para buscar antes de programar algo complicado desde cero.
  • Qt: conjunto de bibliotecas para hacer programas multiplataforma, desde la interfaz gráfica (ventanas, botones) hasta la lógica (qt.io). Si algún día quieres un programa con ventanas, es el nombre que vas a encontrar.
  • SFML: gráficos, sonido y ventanas para juegos 2D, con una interfaz sencilla (sfml-dev.org). Buen primer paso si quieres ver algo moverse en pantalla.

4. Las herramientas del oficio

El depurador: gdb

Hasta ahora depurabas con cout. Un depurador te deja parar el programa en una línea y mirar las variables. GDB sirve para arrancar el programa, pararlo donde quieras, examinar qué pasó y cambiar cosas para probar (GDB). Compila con -g y prueba esto (salida real, recortada):

g++ -g suma.cpp -o prog
gdb ./prog
(gdb) break suma        # para al entrar en la función suma
(gdb) run               # Breakpoint 1, suma (a=2, b=3) at suma.cpp:4
(gdb) next              # ejecuta una línea
(gdb) print r           # $1 = 5
(gdb) bt                # la pila de llamadas: suma ← main (¡lección 3.1!)
(gdb) quit

Los sanitizers: el compilador vigila tu memoria

Ya los usaste sin saberlo: las soluciones de este curso se verificaron con -fsanitize=address,undefined. AddressSanitizer detecta accesos fuera de rango y uso de memoria ya liberada; UndefinedBehaviorSanitizer detecta comportamiento indefinido (GCC — Instrumentation Options). El programa va más lento (unas 2 veces, según la documentación de AddressSanitizer), así que se usa para probar, no para entregar.

int* p = new int(5);
delete p;
cout << *p;          // apuntador colgante (lección 2.3)
g++ -std=c++17 -g -fsanitize=address prueba.cpp -o prog && ./prog
==216539==ERROR: AddressSanitizer: heap-use-after-free on address 0x76e9d17e0010
READ of size 4 at 0x76e9d17e0010 thread T0
    #0 ... in main prueba.cpp:6
freed by thread T0 here:
    #1 ... in main prueba.cpp:5

Te dice qué pasó (usar memoria liberada), dónde la leíste (línea 6) y dónde la liberaste (línea 5). Sin el sanitizer, este programa quizá imprime 5 y parece que funciona. Consejo para tus tareas de listas y pilas: compílalas siempre así mientras las pruebas.

«Funciona en mi máquina» no es una prueba. Un apuntador colgante o un delete doble pueden no fallar hoy y tumbar el programa mañana, o en el ordenador del profesor. -fsanitize=address los convierte en un error claro, con número de línea, la primera vez.

Construir y conseguir bibliotecas

  • CMake: lo viste en la lección 4.6. Para seguir, el tutorial oficial: CMake Tutorial.
  • vcpkg: gestor de paquetes C/C++ libre y de código abierto, mantenido por Microsoft y la comunidad, con más de 2300 bibliotecas; funciona en Windows, macOS y Linux (vcpkg overview).
  • Conan: otro gestor de paquetes para C y C++, de código abierto (licencia MIT) (conan.io).
  • Compiler Explorer: escribes código en el navegador y ves al instante lo que genera el compilador, y puedes ejecutarlo (godbolt.org). Útil para probar algo rápido sin instalar nada.

5. Los estándares: qué trajo cada uno

C++ es un estándar de ISO. La versión oficial vigente es C++23, publicada como ISO/IEC 14882:2024 (isocpp.org — The Standard). Desde C++11 sale una versión cada tres años: 11, 14, 17, 20, 23. En este curso usaste -std=c++17. Lo esencial de cada uno, con lo que ya conoces en negrita:

VersiónLo más importanteFuente
C++11El gran cambio, el «C++ moderno»: auto, for de rango, lambdas, nullptr, semántica de movimiento, unique_ptr/shared_ptr, unordered_map, std::thread, overridecppreference — C++11
C++14Retoques: make_unique, lambdas genéricas, literales binarios y separador de dígitos (1'000'000)C++14
C++17Elisión de copia garantizada (lección 4.7), structured bindings (auto [clave, valor] = par;), if con inicializador, optional, variant, string_view, filesystem, algoritmos paralelosC++17
C++20Cuatro grandes: concepts (plantillas con requisitos), ranges, corrutinas y módulos. Además std::format, span y el operador <=>C++20
C++23std::print, std::expected (devolver resultado o error), import std;, flat_map, mdspanC++23
C++26El comité terminó su trabajo técnico en marzo de 2026; falta la aprobación formal de ISO. Trae reflexión en tiempo de compilación, contratos y std::executionHerb Sutter — C++26 is done!

Para probar algo nuevo cambia el número: -std=c++20. Qué compilador soporta qué está en la tabla de soporte de cppreference. Las novedades de C++20 y C++23 no las necesitas para la universidad; están aquí para que no te suenen a chino cuando las veas.

6. Qué aprender después, según lo que te guste

Elige una ruta. Mejor terminar un proyecto pequeño que empezar cuatro.

Si te gustan los videojuegos

  1. Un juego 2D sencillo (Pong, la serpiente) con SFML. Usa todo el Nivel 4: clases para las entidades, vector para los objetos, apuntadores inteligentes.
  2. Si quieres un motor completo: Godot con godot-cpp o el Quick Start de C++ de Unreal.
  3. Repasa la lección 3.8: en un juego todo se repite 60 veces por segundo y la complejidad se nota.

Si te gustan los embebidos (electrónica, robots)

  1. Una placa Arduino y su referencia del lenguaje. Lo que sabes de C++ se aplica tal cual; lo nuevo es leer pines y sensores.
  2. Después, la Raspberry Pi Pico con su SDK C/C++, que ya se compila con CMake como en la lección 4.6.
  3. Repasa apuntadores y memoria (lecciones 2.2 y 2.3): un microcontrolador tiene muy poca memoria, y ahí cada byte que reservas con new se nota.

Si te gustan los sistemas y el rendimiento

  1. Aprende a medir antes de optimizar: <chrono> (lección 3.8) y Compiler Explorer para ver qué genera el compilador.
  2. Concurrencia: std::thread y después el libro C++ Concurrency in Action.
  3. Usa siempre gdb y los sanitizers. Y lee los capítulos de LearnCpp que no vimos (por ejemplo, constexpr y plantillas avanzadas).

Si te gusta la programación competitiva

  1. Empieza por la sección «Introductory Problems» del CSES Problem Set (más de 400 problemas ordenados por tema).
  2. Sigue la USACO Guide, gratuita, de nivel Bronce a Platino.
  3. Cuando necesites un algoritmo concreto (grafos, programación dinámica), búscalo en cp-algorithms.com, y compite en Codeforces. Las lecciones 4.2 y 4.3 (STL y algoritmos) son tu herramienta principal aquí.

¿Qué pasa en la memoria?

Todo el curso cabe en cuatro zonas: la zona de código, la memoria estática, la memoria automática (la pila de llamadas o stack) y el montón (heap). C++ te deja decidir dónde vive cada cosa y cuándo muere. Es su ventaja (no hay un recolector de basura que pare el programa) y su responsabilidad: si te equivocas, normalmente el compilador no te avisa.

Por eso existen las herramientas. -fsanitize=address vigila la memoria mientras el programa corre: usar algo ya liberado, salirse de un arreglo, liberar dos veces; y en Linux, al terminar, informa de las fugas. Valgrind (valgrind --leak-check=full ./prog, si lo tienes instalado) hace algo parecido sin recompilar, pero más lento. Los contadores de nodos vivos de los miniproyectos son la versión casera: si al final no valen 0, algo se fugó.

En el inventario casi todo se libera solo: el map<string, Producto> es dueño de sus nodos, cada Producto va dentro de su nodo con su string, y el ifstream que abres en cargar cierra el archivo solo al salir de la función. Ni un delete: la regla de cero en acción. La segunda línea de compilación del miniproyecto lo comprueba.

Abre ejercicios/08-panorama.cpp. Es un inventario de tienda que junta casi todo el curso: una clase con un map<string, Producto> dentro, lambdas con sort y accumulate, excepciones y archivos. Ya están hechos el constructor, agregar, cantidadDe y guardar. Completa:

  1. retirar(nombre, cantidad): lanza out_of_range si no existe y runtime_error si no hay bastante; si no, resta (lección 4.4).
  2. valorTotal(): suma de cantidad × precio con accumulate y una lambda (lección 4.3).
  3. bajoStock(limite): los nombres con menos de limite unidades, de menor a mayor, con sort (lecciones 4.2 y 4.3).
  4. cargar(ruta): lee el archivo línea a línea, lo parte con separar y lanza runtime_error si una línea está mal (lecciones 4.4 y 4.6).

Compílalo desde la carpeta ejercicios. Esta vez, ya que sabes cómo, con los sanitizers:

g++ -std=c++17 -Wall 08-panorama.cpp -o prog && ./prog
g++ -std=c++17 -Wall -g -fsanitize=address,undefined 08-panorama.cpp -o prog && ./prog

Al principio verás varias ✗. Terminaste cuando salgan todas en ✓. Unos 20 minutos.

Extra opcional (si te quedaste con ganas): reparte el programa en inventario.h, inventario.cpp y main.cpp y escríbele un Makefile o un CMakeLists.txt, como en la lección 4.6. O añade un menú con cin para usarlo de verdad.

Si te atascas: haz las funciones en orden; cada una tiene una pista encima. Para retirar, busca con productos.find(nombre) igual que cantidadDe, y comprueba todo antes de restar. La solución está en soluciones/08-panorama.cpp; ábrela solo después de intentarlo de verdad.
