Algoritmos y lambdas

Ordenar, buscar, contar y sumar sin escribir el bucle. ~35 minutos.

Al terminar podrás: ordenar, contar, buscar, transformar y sumar los datos de un vector con una sola línea de <algorithm>, pasándole una lambda que diga el criterio, y elegir bien su captura ([x], [&x], [=], [&]).

Por qué. Llevas todo el curso escribiendo los mismos bucles: buscar un valor, contar los que cumplen algo, sumar, encontrar el mayor. Cada bucle a mano es una ocasión de equivocarte en un índice. La STL ya trae esos bucles escritos, probados y rápidos en <algorithm>. Tú solo dices qué quieres con una función pequeña escrita en el sitio: una lambda. Es la forma en que se escribe C++ moderno, y la que vas a leer en cualquier código real.

Calentamiento (3 minutos). Antes de empezar, repite sin mirar el quiz de la lección 4.2.

1. Un algoritmo recibe un rango

Los algoritmos no reciben el contenedor, sino un rango: dos iteradores (4.2), desde begin() hasta end(), sin incluir end(). Así el mismo find sirve para un vector, una lista o un set.

#include <algorithm>

vector<int> v = {5, 2, 8, 2};

sort(v.begin(), v.end());                    // v queda {2, 2, 5, 8}

auto it = find(v.begin(), v.end(), 8);       // iterador al primer 8
if (it != v.end()) cout << "está";           // si no lo encuentra, devuelve end()

cout << count(v.begin(), v.end(), 2);        // 2  (cuántos valen 2)

Como con map::find: find devuelve end() cuando no encuentra nada. Compara siempre antes de usar *it (cppreference, std::find).

2. Lambda: una función sin nombre, escrita en el sitio

¿Y si no buscas «el 8» sino «el primer par»? Le pasas al algoritmo una función que responda la pregunta. Una lambda es eso, escrito justo donde se usa:

[](int x) { return x % 2 == 0; }
// [ ]          captura: qué variables de fuera usa (sección 4)
// (int x)      parámetros, como en cualquier función
// { ... }      cuerpo; el tipo de retorno lo deduce solo

Se puede guardar en una variable con auto y llamar como una función:

auto esPar = [](int x) { return x % 2 == 0; };
cout << esPar(4);    // 1 (true)

Pero lo normal es pasarla directamente al algoritmo.

3. Algoritmos que reciben una lambda

Muchos algoritmos tienen una versión _if que recibe la pregunta:

vector<int> v = {3, 7, 10, 2, 9};

int pares = count_if(v.begin(), v.end(), [](int x) { return x % 2 == 0; });   // 2

auto it = find_if(v.begin(), v.end(), [](int x) { return x > 8; });          // apunta al 10

sort acepta como tercer argumento cómo comparar. La lambda recibe dos elementos y responde: «¿a va antes que b?» (cppreference, std::sort):

sort(v.begin(), v.end(), [](int a, int b) { return a > b; });   // de mayor a menor

struct Alumno { string nombre; double nota; };
vector<Alumno> curso = {{"Luis", 12}, {"Ana", 18}};
sort(curso.begin(), curso.end(), [](const Alumno& a, const Alumno& b) {
    return a.nota > b.nota;                                      // mejor nota primero
});

Así ordenas cualquier cosa, por el criterio que quieras, sin escribir un ordenamiento.

4. Capturas: usar variables de fuera

Una lambda no ve las variables locales de la función donde está escrita, salvo las que capture entre los corchetes:

int limite = 5;
auto grande = [limite](int x) { return x > limite; };   // captura limite (copia)
cout << count_if(v.begin(), v.end(), grande);
EscribesCapturaDentro de la lambda
[]nadasolo sus parámetros
[x]x, por copiala puede leer, no cambiar
[&x]x, por referenciala puede cambiar: cambia la original
[=]todo lo que use, por copialeer
[&]todo lo que use, por referencialeer y cambiar

Es la misma idea que copia contra referencia de la 2.1. Una copia capturada es de solo lectura: la lambda no la puede modificar (cppreference, lambda). Para acumular algo fuera de la lambda, captura por referencia:

int total = 0;
for_each(v.begin(), v.end(), [&](int x) { total += x; });   // [&]: suma en el total de verdad
// con [=] no compila: total sería una copia de solo lectura

Error típico: olvidar la captura.

int limite = 5;
auto grande = [](int x) { return x > limite; };   // error: 'limite' is not captured

Los corchetes vacíos significan «nada de fuera». Arreglo: [limite]. Y al revés, cuidado con [&]: la lambda guarda una referencia, no la variable; si la usas cuando la variable ya murió (por ejemplo, devolviéndola desde una función), es comportamiento indefinido. Dentro de una llamada a un algoritmo, como aquí, no hay problema.

5. for_each y transform: hacer algo con cada uno

for_each llama a la lambda con cada elemento. Si el parámetro es una referencia, puede cambiarlos (cppreference, std::for_each):

for_each(v.begin(), v.end(), [](int& x) { x = x * 2; });   // int&: dobla los de v

transform calcula un resultado por elemento y lo escribe en otro rango. Con back_inserter (de <iterator>) cada resultado se añade con push_back:

#include <iterator>

vector<string> nombres;
transform(curso.begin(), curso.end(), back_inserter(nombres),
          [](const Alumno& a) { return a.nombre; });     // {"Ana", "Luis"}

Error típico: transform hacia un vector vacío. transform(..., nombres.begin(), ...) con nombres vacío escribe en casillas que no existen: comportamiento indefinido, igual que v[5] en un vector de tamaño 0. transform no reserva espacio (cppreference, std::transform). Usa back_inserter(nombres), o crea el destino ya con su tamaño: vector<string> nombres(curso.size());.

6. accumulate: sumarlo todo

accumulate parte de un valor inicial y le va sumando cada elemento. Ojo: no está en <algorithm>, sino en <numeric>.

#include <numeric>

vector<int> v = {3, 7, 10};
int suma = accumulate(v.begin(), v.end(), 0);   // 20

// con lambda: (lo acumulado hasta ahora, el elemento) → nuevo acumulado
double total = accumulate(curso.begin(), curso.end(), 0.0,
    [](double acum, const Alumno& a) { return acum + a.nota; });   // 30

Error típico: 0 en vez de 0.0. El tipo del resultado es el tipo del valor inicial. Con vector<double> v = {1.5, 2.5};, accumulate(v.begin(), v.end(), 0) va guardando en un int y pierde los decimales en cada paso: da 3, no 4. La propia cppreference lo advierte (std::accumulate). Con números con decimales, empieza siempre en 0.0.

7. ¿Y con una list?

find, count_if, for_each, transform y accumulate solo avanzan de uno en uno, así que funcionan igual con una list. sort no: necesita saltar a cualquier posición (como v[i]), y una lista no puede. sort(l.begin(), l.end()) no compila; la lista trae su propio método: l.sort(); (cppreference, list::sort).

¿Qué pasa en la memoria?

Una lambda es un objeto, no solo código. El cuerpo va a la zona de código, como el de cualquier función. Lo capturado va dentro del objeto: auto grande = [limite](int x) {...}; crea en el marco una variable grande que lleva su propia copia de limite. Si después cambias limite, grande no se entera.

Con [&total] o [&] no se copia nada: la lambda guarda un modo de llegar al total original. Aquí importa la diferencia entre ámbito (dónde se puede usar un nombre) y tiempo de vida (cuánto existe la caja). Dentro de for_each, total sigue vivo y todo va bien. Pero si una función devuelve una lambda que capturó por referencia una variable local, el marco de esa función se libera en el return y la lambda se queda con una referencia colgante:

auto crearFiltro() {
    int limite = 5;
    return [&limite](int x) { return x > limite; };   // MAL: limite muere aquí
}                                                      // con [limite] viaja la copia: bien

Miniproyecto 4.3 · Las notas del curso, sin bucles a mano

Abre ejercicios/03-algoritmos-y-lambdas.cpp. Hay un struct Alumno { string nombre; double nota; } (notas de 0 a 20) y seis funciones. Regla del juego: nada de for ni while; cada una es una llamada a un algoritmo con una lambda:

  1. ordenarPorNota: sort, mejor nota primero; en empate, por nombre.
  2. contarAprobados: count_if con una captura.
  3. promedio: accumulate (empieza en 0.0).
  4. nombres: transform con back_inserter.
  5. existe: find_if.
  6. subirNotas: for_each que cambia las notas sin pasar de 20.

Compílalo desde la carpeta ejercicios:

g++ -std=c++17 -Wall 03-algoritmos-y-lambdas.cpp -o prog && ./prog

Al principio verás varias ✗. Terminaste cuando salgan todas en ✓. Unos 20 minutos.

Si te atascas: escribe primero la lambda sola, guardada en un auto, y pruébala con un alumno. Cuando responda bien, pásala al algoritmo. Para el empate de ordenarPorNota: si las notas son distintas, devuelve a.nota > b.nota; si no, a.nombre < b.nombre. La solución está en soluciones/03-algoritmos-y-lambdas.cpp; ábrela solo después de intentarlo de verdad.
