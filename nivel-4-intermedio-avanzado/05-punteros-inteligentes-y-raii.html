Apuntadores inteligentes y RAII

Que la memoria se libere sola, sin escribir delete. ~35 minutos.

Al terminar podrás: escribir una lista enlazada con unique_ptr<Nodo> que no tiene ni un delete, no pierde memoria y no necesita que escribas su destructor.

Antes de empezar: repite sin mirar el quiz de la lección 4.4 (excepciones). La pregunta 5 de ese quiz es justo el problema que se resuelve hoy.

Por qué. En el Nivel 3 cada estructura necesitó su destructor con un bucle de delete, y en la lección 3.5 viste que copiarla mal termina en un doble delete. En C++ moderno casi nunca se escribe delete: se deja a un objeto que lo haga por ti. Es la diferencia más visible entre el C++ de la universidad y el C++ de un proyecto real.

1. ¿Quién es el dueño de esta memoria?

Con new/delete a mano hay tres maneras clásicas de fallar:

FalloEjemplo
olvidar el deleteuna función con dos return y el delete solo en uno
una excepción salta el deleteel ejemplo de la sección 6 de la lección 4.4
dos delete del mismo nodola copia superficial de la lección 3.5

Los tres son el mismo problema: no está claro quién es el dueño de esa memoria, es decir, quién tiene que liberarla.

2. RAII: el destructor libera

RAII viene del inglés Resource Acquisition Is Initialization («adquirir el recurso es inicializar»). El nombre es malo; la idea es sencilla:

Un objeto toma el recurso en su constructor y lo suelta en su destructor.

Como C++ siempre llama al destructor de una variable local cuando su bloque termina —por un return, por llegar a la llave } o porque subió una excepción—, el recurso se libera siempre (cppreference — RAII).

Ya lo usas sin saberlo: vector y string piden memoria por dentro y la liberan en su destructor. Nunca has escrito delete para un vector. En la lección 4.6 verás que ifstream hace lo mismo con los archivos: los cierra al destruirse.

3. unique_ptr y make_unique

Un apuntador inteligente (en inglés, smart pointer) es un objeto que se comporta como un apuntador pero aplica RAII a la memoria. El principal es std::unique_ptr, en <memory>: es el dueño único de lo que apunta, y lo libera al destruirse (cppreference — unique_ptr).

#include <memory>

{
    unique_ptr<Nodo> p = make_unique<Nodo>(4);   // crea el Nodo (hace el new por ti)
    cout << p->dato;                              // 4  — se usa como un Nodo*
    Nodo* mirar = p.get();                        // apuntador normal que solo MIRA
    if (p) cout << "tiene algo";                  // se puede preguntar como un apuntador
}   // aquí muere p → libera el Nodo. Ningún delete.

make_unique existe desde C++14 y es la forma recomendada de crearlo.

No se copia: se mueve

«Único» es literal: dos unique_ptr no pueden ser dueños de lo mismo. Copiarlo no compila. Lo que sí puedes es pasar la propiedad a otro con std::move; el de origen queda en nullptr.

auto a = make_unique<int>(4);
auto b = a;          // ERROR de compilación: use of deleted function
auto c = move(a);    // bien: ahora c es el dueño y a queda en nullptr

Qué hace move por dentro lo verás en la lección 4.7. Por ahora: «move = pásale la propiedad».

Error típico: usar un unique_ptr después de moverlo.

auto c = move(a);
cout << *a;     // a es nullptr: desreferenciarlo, igual que en la lección 2.2

Y otro: crear dos unique_ptr a partir del mismo apuntador normal (unique_ptr<int> x(p), y(p);). Los dos harán delete: doble liberación. Con make_unique este error no se puede cometer.

4. La lista enlazada con unique_ptr

Ahora el cambio grande. Solo cambia el tipo de siguiente y de cabeza:

struct Nodo {
    int dato;
    unique_ptr<Nodo> siguiente;     // antes: Nodo* siguiente;
    Nodo(int d) : dato(d), siguiente(nullptr) {}
};

class ListaEnlazada {
private:
    unique_ptr<Nodo> cabeza;        // antes: Nodo* cabeza;
public:
    // ¡No hay destructor! Ni bucle de delete.
    ...
};

Lee la cadena de dueños: la lista es dueña de la cabeza, la cabeza es dueña del segundo, el segundo del tercero...

lista.cabeza
dueño de → [1]
[1].siguiente
dueño de → [2]
[2].siguiente
dueño de → [3]
[3].siguiente
nullptr

Cuando la lista muere, muere su cabeza, que libera el nodo 1; al morir el nodo 1 muere su siguiente, que libera el 2... Toda la lista se libera sola. Por eso ya no hace falta escribir el destructor.

Insertar al inicio

void insertarAlInicio(int valor) {
    unique_ptr<Nodo> nuevo = make_unique<Nodo>(valor);
    nuevo->siguiente = move(cabeza);   // el nuevo se queda con la cabeza vieja
    cabeza = move(nuevo);              // la lista se queda con el nuevo
}

Son los mismos dos pasos de la lección 3.2, con move donde antes había un = entre apuntadores.

Recorrer: un apuntador normal que solo mira

Para recorrer no quieres ser dueño de nada, solo mirar. Para eso está .get(), que da un Nodo* normal:

void imprimir() const {
    for (Nodo* p = cabeza.get(); p != nullptr; p = p->siguiente.get()) {
        cout << p->dato << " ";
    }
}

Regla: unique_ptr para el que es dueño, Nodo* para el que solo mira. Un Nodo* que mira nunca hace delete.

Eliminar el primero: una línea

cabeza = move(cabeza->siguiente);   // la cabeza pasa a ser el segundo...
                                    // ...y el primero, sin dueño, se libera solo

5. Regalo: la copia peligrosa ya no compila

En la lección 3.5, copiar una ListaEnlazada compilaba y explotaba al ejecutar (doble delete). Ahora, como unique_ptr no se copia, el compilador tampoco sabe copiar la lista:

ListaEnlazada l1;
ListaEnlazada l2 = l1;   // error: use of deleted function 'ListaEnlazada(const ListaEnlazada&)'

Un error al compilar es muchísimo mejor que uno al ejecutar. Si de verdad necesitas copiar, escribes la copia profunda como en la 3.5.

6. Cuidado: las listas muy largas

La liberación «en cadena» de la sección 4 tiene un precio: es recursiva. El destructor del nodo 1 llama al del nodo 2, que llama al del 3... Cada llamada ocupa sitio en la pila de llamadas (lección 3.1), que es pequeña (unos 8 MB en Linux).

Lo medí con g++ -std=c++17 sin optimizar: una lista de 10 000 nodos se libera bien; una de 100 000 hace caer el programa con Violación de segmento. cppreference avisa de lo mismo en el ejemplo de su página de unique_ptr: el destructor por defecto «invocaría el destructor de next recursivamente, lo que desbordaría la pila con listas suficientemente grandes».

La solución: liberar con un bucle, un nodo cada vez, usando la misma línea de «eliminar el primero»:

~ListaEnlazada() {
    while (cabeza) {
        cabeza = move(cabeza->siguiente);   // libera UN nodo; su siguiente ya está vacío
    }
}

Cada vuelta libera un nodo cuyo siguiente ya se movió (está en nullptr), así que no hay cadena. Fíjate: este destructor no tiene delete y no es para no perder memoria (eso ya está garantizado), solo para no gastar pila. Para listas de clase, de unos cientos de nodos, no hace falta.

7. shared_ptr y weak_ptr (mención)

A veces una cosa tiene varios dueños y debe vivir mientras quede al menos uno. Para eso está std::shared_ptr: lleva un contador de dueños y libera cuando llega a 0.

auto s1 = make_shared<int>(3);
auto s2 = s1;                    // este SÍ se copia: ahora hay 2 dueños
cout << s1.use_count();          // 2

Su punto débil son los ciclos: si A tiene un shared_ptr a B y B uno a A, el contador nunca llega a 0 y nadie se libera. Para romper el ciclo, uno de los dos lados usa std::weak_ptr, que mira sin contar como dueño (LearnCpp 22.7). En una lista doble con unique_ptr, el anterior sería un Nodo* que solo mira, por el mismo motivo.

Regla práctica: empieza siempre por unique_ptr. Pasa a shared_ptr solo si de verdad hay varios dueños.

¿Qué pasa en la memoria?

Un unique_ptr ocupa normalmente lo mismo que un apuntador normal (compruébalo con sizeof): no lleva nada extra. La diferencia es que es dueño, y su destructor hace el delete. En tu lista, cabeza vive dentro del objeto lista (en el marco, si la lista es local) y cada siguiente vive dentro de un nodo del montón (heap). La cadena de dueños baja por el montón, y por eso basta con que muera la lista para que se libere todo.

shared_ptr es más pesado. Normalmente guarda dos apuntadores: uno al objeto y otro a un bloque de control en el montón, donde viven el contador de dueños y el de weak_ptr. make_shared<int>(3) pide una sola reserva para el bloque y el int juntos. auto s2 = s1; no copia el 3: solo suma 1 al contador. Cuando el contador de dueños llega a 0 se destruye el objeto, y el bloque se libera cuando tampoco queda ningún weak_ptr mirándolo.

Abre ejercicios/05-punteros-inteligentes-y-raii.cpp. El Nodo ya tiene unique_ptr<Nodo> siguiente y un contador de nodos vivos. Regla del juego: ni un new ni un delete. Completa:

  1. insertarAlInicio(valor): con make_unique y dos move.
  2. insertarAlFinal(valor): camina con un Nodo* que solo mira (.get()).
  3. eliminarPrimero(): quita el primero; devuelve false si la lista estaba vacía.
  4. vaciar(): libera nodo a nodo con un bucle. El destructor ya la llama, y una prueba crea una lista de un millón de nodos.
