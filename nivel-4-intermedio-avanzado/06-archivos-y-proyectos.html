Archivos y proyectos de varios archivos

Que tus datos sobrevivan al programa, y que tu código quepa en más de un archivo. ~35 minutos.

Al terminar podrás: guardar y cargar datos en un archivo de texto, partir un programa en .h + .cpp + main.cpp y compilarlo con g++, con un Makefile o con CMake.

Antes de empezar: repite sin mirar el quiz de la lección 4.5 (apuntadores inteligentes y RAII). Fíjate en la última pregunta, la de RAII: hoy la vas a ver otra vez, con archivos.

Por qué. Hasta ahora, al cerrar el programa se perdía todo. Y todo vivía en un solo .cpp. Un proyecto de la universidad (y cualquiera de verdad) necesita las dos cosas: guardar datos y repartir el código en varios archivos. Son dos ideas distintas, pero van juntas en el mismo miniproyecto: una agenda que se guarda en disco, repartida en tres archivos.

1. Escribir un archivo: ofstream

Un archivo se escribe igual que la pantalla. Cambias cout por un objeto ofstream («output file stream», flujo de salida a archivo):

#include <fstream>

ofstream archivo("/tmp/notas.txt");   // abre el archivo (lo crea o lo VACÍA)
if (!archivo) {                       // ¿se pudo abrir?
    cout << "No pude abrirlo\n";
    return 1;
}
archivo << "Ana" << " " << 18 << "\n";   // igual que cout
// al terminar el bloque, el archivo se cierra solo

Tres cosas que importan:

  • Compruébalo siempre con if (!archivo). Si la carpeta no existe o no tienes permiso, la apertura falla en silencio: todo lo que escribas se pierde.
  • Abrirlo así borra lo que tenía. Para añadir al final, ábrelo con ofstream archivo(ruta, ios::app); («append»).
  • No hace falta close(). El destructor de ofstream cierra el archivo al salir del bloque. Es RAII, lo mismo que hacía unique_ptr con la memoria en la lección 4.5.

2. Leer un archivo: ifstream

Para leer, ifstream («input file stream»). Se usa como cin. Hay dos formas, según lo que quieras:

ifstream archivo("/tmp/numeros.txt");
int n;
while (archivo >> n) {            // >> lee PALABRA a palabra (se para en espacios)
    cout << n << "\n";            // el bucle termina cuando ya no hay más
}
ifstream archivo("/tmp/contactos.txt");
string linea;
while (getline(archivo, linea)) {  // getline lee la LÍNEA entera, con espacios
    cout << linea << "\n";
}

Usa >> para números sueltos. Usa getline cuando una línea puede tener espacios, como Ana Pérez: con >> solo leerías Ana.

El error clásico: while (!archivo.eof()).

while (!archivo.eof()) {      // MAL: da una vuelta de más
    getline(archivo, linea);
    lineas++;
}

eof() solo se activa después de intentar leer y fallar. Con un archivo de 2 líneas, el bucle da 3 vueltas, y la última no leyó nada. Pon la lectura dentro de la condición: while (getline(archivo, linea)). Así el bucle para justo cuando una lectura falla.

3. Guardar datos con formato: una línea por registro

Para guardar objetos, inventa un formato sencillo: un registro por línea y los campos separados por un carácter que no aparezca en los datos. Por ejemplo ;:

Ana Pérez;0414-555
Luis;0212-777

Guardar es escribir los campos con el ; en medio. Cargar es lo contrario: leer la línea y partirla con find y substr, que ya viste en la lección 1.7:

string linea = "Ana Pérez;0414-555";
size_t pos = linea.find(';');                // 9: dónde está el ';'
if (pos != string::npos) {                   // npos = «no lo encontré»
    string nombre   = linea.substr(0, pos);  // "Ana Pérez"
    string telefono = linea.substr(pos + 1); // "0414-555"
}

Si una línea viene vacía o rota, sáltala (o lanza una excepción, como en la lección 4.4). Un archivo lo puede editar cualquiera: no te fíes de él.

4. Partir el programa: .h y .cpp

Cuando un programa crece, se reparte. La regla es siempre la misma:

ArchivoQué llevaEjemplo
agenda.hDeclaraciones: qué existe (structs, clases, prototipos)bool guardarNumeros(...);
agenda.cppDefiniciones: el código de las funcionesbool guardarNumeros(...) { ... }
main.cppUsa lo de arriba#include "agenda.h"

El .h es la «carta de presentación»: dice qué hay. El .cpp dice cómo se hace. Quien usa la agenda solo necesita la carta. Son los prototipos de la lección 1.6, puestos en su propio archivo.

// agenda.h
#ifndef AGENDA_H
#define AGENDA_H
#include <string>
#include <vector>

std::vector<int> cargarNumeros(const std::string& ruta);   // solo el prototipo

#endif
// agenda.cpp
#include "agenda.h"        // comillas: archivo tuyo. <...>: de la biblioteca
#include <fstream>
using namespace std;

vector<int> cargarNumeros(const string& ruta) {
    // ... el código de verdad ...
}

Una excepción que ya conoces: las plantillas van enteras en el .h, como viste en la lección 4.1.

5. Los guardias de inclusión

#include es literalmente «pega aquí el archivo». Si main.cpp incluye agenda.h y también otro .h que a su vez incluye agenda.h, el struct Contacto aparece dos veces, y el compilador se queja: redefinition of 'struct Contacto'.

Las tres líneas #ifndef / #define / #endif lo evitan. Leen así: «si todavía no se definió AGENDA_H, defínelo y pega esto; si ya estaba, sáltatelo».

Existe una forma corta, #pragma once en la primera línea. Casi todos los compiladores la aceptan, pero no es parte del estándar; por eso LearnCpp recomienda los guardias clásicos (LearnCpp 2.12 — Header guards). Cualquiera de las dos sirve; lo que no sirve es no poner ninguna.

Dos cosas que NO van en un .h:

1. using namespace std; — se colaría en todos los archivos que lo incluyan. En el .h escribe std::string; en el .cpp sí puedes usarlo.

2. El cuerpo de una función normal. Si dos .cpp incluyen ese .h, la función queda definida dos veces y el enlazador protesta: multiple definition of ... (LearnCpp 2.11 — Header files).

6. Compilar varios archivos con g++

Le das a g++ todos los .cpp. Los .h no se ponen: ya entran por los #include.

g++ -std=c++17 -Wall main.cpp agenda.cpp -o prog && ./prog

Por dentro pasan dos fases. Primero, cada .cpp se compila por su cuenta a un archivo objeto (.o). Luego el enlazador («linker») junta los .o en el programa:

Puedes hacer las dos fases a mano. La ventaja: si solo cambias agenda.cpp, solo recompilas ese:

g++ -std=c++17 -Wall -c main.cpp       # -c: solo compila → main.o
g++ -std=c++17 -Wall -c agenda.cpp     #                  → agenda.o
g++ main.o agenda.o -o prog            # enlaza → prog

undefined reference to `guardarNumeros(...)' no es un error de compilación: es del enlazador. Casi siempre significa que olvidaste un .cpp en el comando (g++ main.cpp -o prog), o que el nombre o los parámetros del .cpp no coinciden con el prototipo del .h.

7. Un Makefile mínimo

Escribir esos comandos cada vez cansa. make los lee de un archivo llamado Makefile. Cada regla dice: objetivo, de qué depende y cómo se hace:

CXX = g++
CXXFLAGS = -std=c++17 -Wall

prog: main.o agenda.o
	$(CXX) $(CXXFLAGS) main.o agenda.o -o prog

main.o: main.cpp agenda.h
	$(CXX) $(CXXFLAGS) -c main.cpp

agenda.o: agenda.cpp agenda.h
	$(CXX) $(CXXFLAGS) -c agenda.cpp

clean:
	rm -f *.o prog

Escribes make y construye prog. Lo bueno: mira las fechas de los archivos y solo recompila lo que cambió. Si tocas agenda.cpp, rehace agenda.o y prog, pero no main.o. Si lo corres sin cambios, dice 'prog' está actualizado. make clean borra lo generado.

Las líneas de comando de un Makefile empiezan con TABULADOR, no con espacios. Si tu editor pone espacios, make responde missing separator. Es el error número uno con make.

8. CMake mínimo (opcional)

Un Makefile solo sirve donde hay make. CMake describe el proyecto una vez y genera lo que cada sistema necesite (un Makefile en Linux, un proyecto de Visual Studio en Windows...). Es lo que usan casi todos los proyectos grandes de C++. Para este proyecto basta con esto, en un archivo CMakeLists.txt:

cmake_minimum_required(VERSION 3.16)
project(Agenda CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

add_executable(prog main.cpp agenda.cpp)
cmake -S . -B build        # configura: -S dónde está el código, -B dónde construir
cmake --build build        # compila
./build/prog

Todo lo generado queda en la carpeta build; tu código no se ensucia. Comprueba si lo tienes con cmake --version. Si no está instalado, no pasa nada: esta sección es opcional y el miniproyecto funciona con g++ o make. (En Ubuntu/Debian se instala con sudo apt install cmake.) El tutorial oficial empieza aquí: CMake Tutorial.

¿Qué pasa en la memoria?

Un ofstream o un ifstream es una variable más del marco, pero es dueño de algo que no es memoria: un archivo abierto que el sistema operativo te presta. Por eso sigue RAII, igual que unique_ptr: al salir del bloque, su destructor manda lo pendiente y cierra el archivo.

Además lleva un búfer: un trozo de memoria donde junta lo que escribes (archivo << "Ana") para mandarlo al disco de una vez, no letra a letra. Si el programa se cae antes de que corra el destructor, lo que quedaba en el búfer puede no llegar nunca al archivo. Al leer, getline copia cada línea en linea, un string que guarda sus letras en el montón y normalmente reaprovecha ese espacio en cada vuelta.

Partir el programa en agenda.h, agenda.cpp y main.cpp no cambia nada de esto: es una forma de organizar el código para compilarlo. Al ejecutar, prog es un solo programa, con una zona de código que junta las funciones de main.o y agenda.o.

Miniproyecto 4.6 · Agenda en archivos

Esta vez el ejercicio es una carpeta: ejercicios/06-archivos-y-proyectos/. Dentro hay cinco archivos:

  • agenda.h: declaraciones (no tocar). Mírala: tiene su guardia de inclusión.
  • agenda.cpp: aquí trabajas.
  • main.cpp: las pruebas (no tocar).
  • Makefile y CMakeLists.txt: los de las secciones 7 y 8.

Completa en agenda.cpp:

  1. guardarNumeros: un número por línea; false si no se pudo abrir.
  2. cargarNumeros: con while (archivo >> n); vacío si el archivo no existe.
  3. guardarContactos: una línea nombre;telefono por contacto.
  4. cargarContactos: con getline, find y substr; salta las líneas sin ;.

Compílalo desde la carpeta ejercicios/06-archivos-y-proyectos, de la forma que quieras:

g++ -std=c++17 -Wall main.cpp agenda.cpp -o prog && ./prog
make && ./prog
cmake -S . -B build && cmake --build build && ./build/prog     # opcional

Prueba al menos una vez con make: compila, cambia algo en agenda.cpp y vuelve a escribir make. Verás que solo recompila ese archivo. Los datos se guardan en /tmp, así no ensucian tu carpeta. Al principio verás varias ✗. Terminaste cuando salgan todas en ✓. Unos 20 minutos.

Si te atascas: empieza por guardarNumeros y mira el archivo que crea con cat /tmp/curso-cpp-46-numeros.txt (comenta la última línea remove(...) de main.cpp un momento para que no se borre). Ver el archivo real aclara casi todo. Cada función tiene una pista encima. La solución está en soluciones/06-archivos-y-proyectos/agenda.cpp; ábrela solo después de intentarlo de verdad.
