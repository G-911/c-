Plantillas

Escribes la Pila una vez y sirve para cualquier tipo. ~35 minutos.

Al terminar podrás: convertir tu Pila de enteros en una Pila<T> que guarda int, string o lo que quieras, y explicar por qué su código va entero en el .h.

Por qué empieza aquí el Nivel 4. Tu Pila de la lección 3.6 solo guarda int. Si mañana necesitas una pila de string, tendrías que copiar la clase entera y cambiar int por string a mano. Las plantillas (en inglés, templates) hacen ese copiar-y-cambiar por ti. Además, ya las usas sin saberlo: vector<int> y stack<string> son plantillas. Toda la biblioteca estándar (la STL de las lecciones 4.2 y 4.3) está hecha así.

Calentamiento (3 minutos). Antes de empezar, repite sin mirar el quiz de la lección 3.9. Recordar lo de hace días es lo que lo fija.

1. El problema: la misma función, una vez por tipo

Quieres el mayor de dos valores. Con sobrecarga (lección 1.6) escribes una versión por tipo:

int    maximo(int a, int b)       { return (a > b) ? a : b; }
double maximo(double a, double b) { return (a > b) ? a : b; }
string maximo(string a, string b) { return (a > b) ? a : b; }
// ...y otra para char, otra para long...

Las tres son idénticas. Solo cambia el tipo. Eso es justo lo que resuelve una plantilla.

2. Función plantilla

Escribes la función una vez, con un nombre de tipo inventado (T) en lugar del tipo real:

template <typename T>          // «T es un tipo que se decide después»
T maximo(T a, T b) {
    return (a > b) ? a : b;
}

cout << maximo(3, 8);                         // 8      (T = int)
cout << maximo(2.5, -1.0);                    // 2.5    (T = double)
cout << maximo(string("ana"), string("beto")); // beto   (T = string)

Qué pasa por dentro: la plantilla no es una función. Es un molde. Cuando escribes maximo(3, 8), el compilador mira los argumentos, deduce T = int y fabrica una función maximo para int. Eso se llama instanciar la plantilla. Con 2.5 fabrica otra para double. Tú solo escribiste una.

También puedes decir el tipo a mano, entre <>:

cout << maximo<double>(3, 2.5);   // 3 se convierte a 3.0 → muestra 3

Error típico: mezclar tipos. maximo(3, 2.5) no compila. El primer argumento dice «T es int», el segundo «T es double», y el compilador no elige por ti. El mensaje dice algo como deduced conflicting types for parameter 'T'. Arreglo: pasa los dos del mismo tipo (3.0, 2.5) o escribe maximo<double>(3, 2.5).

3. Lo que la plantilla le pide a T

maximo usa a > b. Entonces solo funciona con tipos que saben compararse con >. Con int, double y string sí. Con una clase tuya sin operator> (lección 2.7), no: el error sale cuando instancias, y suele ser largo. Léelo desde la línea que nombra tu archivo.

Regla práctica: lo que el cuerpo le haga a T (comparar, sumar, copiar, imprimir con <<), el tipo que uses tiene que saber hacerlo.

4. Clase plantilla: de Pila a Pila<T>

Lo mismo vale para una clase. Toma tu Pila de la 3.6 y haz tres cambios:

Pila de enteros (3.6)Pila genérica
(nada)template <typename T> encima de Nodo y encima de Pila
int dato; · push(int valor) · int top()T dato; · push(const T& valor) · T top()
Nodo*Nodo<T>*

Todo lo demás —tope, el orden de las flechas, el destructor— queda igual:

template <typename T>
struct Nodo {
    T dato;                // antes: int dato;
    Nodo* siguiente;       // dentro de la plantilla, «Nodo» ya significa Nodo<T>
    Nodo(const T& d) : dato(d), siguiente(nullptr) {}
};

template <typename T>
class Pila {
private:
    Nodo<T>* tope;        // el de arriba; nullptr si está vacía

public:
    Pila() : tope(nullptr) {}

    ~Pila() {
        Nodo<T>* actual = tope;
        while (actual != nullptr) {
            Nodo<T>* sig = actual->siguiente;
            delete actual;
            actual = sig;
        }
    }

    bool vacia() const { return tope == nullptr; }

    int tamano() const {
        int n = 0;
        for (Nodo<T>* p = tope; p != nullptr; p = p->siguiente) n++;
        return n;
    }

    void push(const T& valor) {       // const T&: no copia un string grande sin necesidad (2.1)
        Nodo<T>* nuevo = new Nodo<T>(valor);
        nuevo->siguiente = tope;
        tope = nuevo;
    }

    void pop() {                       // sobre una pila vacía no hace nada
        if (vacia()) return;
        Nodo<T>* viejo = tope;
        tope = tope->siguiente;
        delete viejo;
    }

    T top() const { return tope->dato; }   // precondición: !vacia()
};

¿Y la regla de tres? Esta Pila tiene destructor, así que copiarla con el constructor de copia por defecto daría doble delete (lección 3.5). En el miniproyecto verás dos líneas que lo prohíben: Pila(const Pila&) = delete; y Pila& operator=(const Pila&) = delete;. = delete significa «esta operación no existe»: si alguien intenta copiar, no compila.

5. Usarla

Pila<int> numeros;
numeros.push(1);
numeros.push(2);
cout << numeros.top();     // 2

Pila<string> palabras;
palabras.push("hola");
palabras.push("mundo");
palabras.pop();
cout << palabras.top();    // hola

Pila<char> simbolos;       // la de los paréntesis balanceados de la 3.6

Fíjate: Pila sola no es un tipo. Es el molde. Pila<int> y Pila<string> sí son tipos, y son tipos distintos: no puedes asignar uno al otro. Por eso Pila p; no compila: falta decir de qué.

Métodos escritos fuera de la clase

Algunos profesores piden escribir los métodos fuera de la clase. Con plantillas, cada uno repite el template y dice Pila<T>:::

template <typename T>
void Pila<T>::push(const T& valor) {    // dentro de la clase solo queda: void push(const T& valor);
    Nodo<T>* nuevo = new Nodo<T>(valor);
    nuevo->siguiente = tope;
    tope = nuevo;
}

6. Por qué la plantilla va entera en el .h

Con una clase normal separas: declaración en Pila.h, código en Pila.cpp (lo practicarás en la 4.6). Con una plantilla eso falla.

La razón está en la sección 2: el compilador fabrica Pila<int> en el momento en que alguien la usa, y para eso necesita ver el código completo en ese archivo. El compilador trabaja archivo por archivo:

  • Al compilar main.cpp ve Pila<int>, pero del .h solo le llegaron las declaraciones. No puede fabricar los métodos.
  • Al compilar Pila.cpp ve el código, pero ahí nadie usa Pila<int>. No fabrica nada.

Resultado: nadie fabricó Pila<int>::push, y el enlazador (el último paso de g++) se queja (LearnCpp 26.1, «Splitting up template classes»).

Error típico: separar la plantilla en .h y .cpp. Compila cada archivo bien, pero al final sale undefined reference to `Pila<int>::push(int const&)' (con el sistema en español: referencia a `Pila<int>::push(int const&)' sin definir). No es que el método no exista: es que nadie lo fabricó. Arreglo: todo el código de la plantilla en el .h. Es lo que hace la propia biblioteca estándar.

¿Qué pasa en la memoria?

Una plantilla no ocupa memoria mientras el programa corre: es un molde que solo usa el compilador. Lo que sí existe son las versiones que fabricó. Si usas Pila<int>, Pila<string> y Pila<char>, en la zona de código quedan tres juegos de push, pop y top, uno por tipo. Más tipos distintos, programa un poco más grande.

Los datos viven donde siempre. numeros está en el marco de main, en la memoria automática (la pila de llamadas o stack; no es tu clase Pila), y solo guarda tope. Cada push pone un nodo en el montón (heap) y el destructor los libera, como en la 3.6. Lo que cambia con T es el tamaño de cada nodo: sizeof(Nodo<char>) es normalmente menor que sizeof(Nodo<string>), y un string largo guarda además sus letras en otro trozo del montón.

Miniproyecto 4.1 · Una Pila<T> que sirve para todo

Abre ejercicios/01-plantillas.cpp. La Pila<T> viene a medias: vacia, tamano y el destructor están hechos. Completa:

  1. maximo(T a, T b): la función plantilla de la sección 2.
  2. push, pop y top de Pila<T>: los de la 3.6, cambiando int por T y Nodo por Nodo<T>.
  3. invertir(const vector<T>& v): una función plantilla que usa tu Pila<T> para dar la vuelta a un vector.

Las pruebas usan la misma Pila con int, string y char, y comprueban que no quedan nodos sin liberar. Compílalo desde la carpeta ejercicios:

g++ -std=c++17 -Wall 01-plantillas.cpp -o prog && ./prog

Al principio verás varias ✗. Terminaste cuando salgan todas en ✓. Unos 20 minutos.

Si te atascas: abre tu Pila de la 3.6 al lado y cambia palabra por palabra, como en la tabla de la sección 4. En top(), lo que había que devolver sigue siendo tope->dato. La solución está en soluciones/01-plantillas.cpp; ábrela solo después de intentarlo de verdad.
