Concurrencia

Hoja de consulta rápida de las lecciones 6.1 y 6.2.

Compilar

g++ -std=c++20 -Wall -pthread prog.cpp -o prog && ./prog                        # normal
g++ -std=c++20 -Wall -pthread -fsanitize=thread -g prog.cpp -o prog && ./prog    # busca carreras de datos

-fsanitize=thread no se combina con -fsanitize=address: compila dos veces. -std=c++20 solo hace falta por jthread; lo demás es C++11/17.

Hilos (#include <thread>)

EscribesSignifica
thread t(f, a, b);arranca f(a, b) en otro hilo; copia los argumentos
thread t(f, ref(x));pasa x por referencia (<functional>)
thread t([&] { ... });con lambda; ojo con lo capturado por referencia
t.join();espera a que termine; obligatorio (si no, std::terminate)
jthread j(f);hace join() solo en su destructor (C++20)
vector<thread> hs; hs.push_back(thread(f));varios hilos; thread se mueve, no se copia
thread::hardware_concurrency()hilos simultáneos del hardware; pista; 0 si no lo sabe

Proteger datos compartidos (#include <mutex>)

EscribesSignifica
mutex m;un cerrojo: un hilo a la vez
lock_guard<mutex> c(m);cierra hasta el final del bloque (RAII)
scoped_lock c(m1, m2);cierra varios a la vez sin interbloqueo (C++17)
unique_lock<mutex> c(m);como lock_guard, pero con unlock()/lock(); lo pide wait
m.lock(); ... m.unlock();a mano: evítalo (un return o una excepción lo deja cerrado)

Atómicos (#include <atomic>)

EscribesSignifica
atomic<int> c = 0;entero compartido sin mutex
c++; c += 5; c.fetch_add(1);sumas atómicas (un solo paso)
c.load() / c.store(v)leer / escribir atómicamente
c = c + 1;MAL: un load y un store separados; se pierden sumas
memory_order_...para expertos; por defecto seq_cst, el más seguro

Esperar un aviso (#include <condition_variable>)

// quien espera
unique_lock<mutex> candado(m);
cv.wait(candado, [&] { return !cola.empty() || cerrada; });   // SIEMPRE con condición y con salida

// quien avisa
{ lock_guard<mutex> candado(m); cola.push(x); }   // 1.º cambiar el dato, protegido
cv.notify_one();                                  // 2.º avisar (notify_all al cerrar)

Resultados en paralelo (#include <future>)

EscribesSignifica
future<int> f = async(launch::async, g, x);calcula g(x) en otro hilo
f.get()espera y devuelve el valor; si g lanzó, relanza aquí; una sola vez
f.wait_for(chrono::seconds(10))espera con tiempo máximo; devuelve future_status::ready o timeout
async(launch::async, g); sin guardarMAL: el future temporal espera ahí mismo; queda secuencial

¿Cuál uso?

NecesitasUsa
calcular en paralelo y recoger un resultadoasync + future
un contador o bandera compartidosatomic
cambiar varios datos juntosmutex + lock_guard / scoped_lock
que un hilo espere a otrocondition_variable
un hilo trabajador de larga vidajthread

Primero intenta no compartir: cada hilo con sus datos y un resultado al final.

Errores típicos

ErrorQué pasaCómo evitarlo
dos hilos escriben una variable sin proteccióncarrera de datos: comportamiento indefinido (puede «funcionar» con -O2)mutex o atomic; comprueba con -fsanitize=thread
thread destruido sin join()std::terminate: el programa abortajoin() siempre, o jthread
dos mutex cerrados en orden distintointerbloqueo: el programa se congelascoped_lock(m1, m2) o siempre el mismo orden
wait sin condición de salidael hilo duerme para siemprela condición incluye «terminado/cerrada» + notify_all
lambda con [&] que vive más que la funciónel hilo escribe en un marco ya liberadojoin() antes del return
capturar el índice del bucle por referenciael hilo lee un índice que ya cambiócaptura i por copia: [&v, i]
