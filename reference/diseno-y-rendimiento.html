Técnicas de C++

PIMPL

// x.h
class X {
public:
    X();
    ~X();                          // SOLO declarado aquí
    X(X&&) noexcept;
    X& operator=(X&&) noexcept;
private:
    struct Impl;                   // declarada, no definida
    std::unique_ptr<Impl> impl;
};

// x.cpp
struct X::Impl { /* los atributos de verdad */ };
X::X() : impl(std::make_unique<Impl>()) {}
X::~X() = default;                 // aquí Impl ya está completa
X::X(X&&) noexcept = default;
X& X::operator=(X&&) noexcept = default;

Si pones ~X() = default; en el .h: invalid application of ‘sizeof’ to incomplete type.

CRTP

template <typename D>
class Base {
public:
    void comun() const { static_cast<const D&>(*this).concreto(); }
};
class Hija : public Base<Hija> {   // se pasa a sí misma
public:
    void concreto() const { /* ... */ }
};

Sin virtual, se resuelve al compilar. Pero Base<A> y Base<B> son tipos distintos: no van en el mismo vector.

Type erasure

class Dibujable {
    struct Concepto { virtual ~Concepto() = default; virtual void dibujar() const = 0; };
    template <typename T> struct Modelo : Concepto {
        T obj;
        Modelo(T o) : obj(std::move(o)) {}
        void dibujar() const override { obj.dibujar(); }
    };
    std::unique_ptr<Concepto> caja;
public:
    template <typename T> Dibujable(T o) : caja(std::make_unique<Modelo<T>>(std::move(o))) {}
    void dibujar() const { caja->dibujar(); }
};

Ejemplo listo para usar: std::function<R(Args...)> guarda funciones, lambdas y objetos con operator().

Con UB, -O0 y -O2 pueden dar resultados distintos, y los dos son «válidos». El compilador supone que el UB nunca ocurre.
